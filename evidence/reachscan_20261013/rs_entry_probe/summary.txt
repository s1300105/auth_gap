reachscan v0.4.0（4f6509d）の Python 入口検出は表駆動の AST 照合で、①デコレータ（`@obj.name` の 2 段まで、末尾名 10 語）、②基底クラス BaseTool / StructuredTool / Toolkit＋静的な `name`、③モジュール直下の工場呼び出し 6 形を読む。関数本体に降りるのは call_tool / list_tools だけ。合成ケースの実行で、serve() 内の低レベルハンドラは拾うが、工場関数内の `@srv.tool`、if / try 内の定義、`@self.mcp.tool` 等の 3 段、`add_tool(fn)` と `mcp.tool(...)(fn)`、`Server(on_call_tool=)`、BOM 付きファイル、祖先に tests を持つ木は入口にならないと確かめた。注釈は framework ラベルが mcp の入口でだけ読まれ、ラベルは受け手名か import 推論で決まるため、`srv = fastmcp.FastMCP()` などでは読まれない。低レベルは同じファイルの list_tools 本体とモジュール直下の `Tool(name=…)` を、同じファイルの call_tool の第 1 仮引数への `==`（and 可）/ match の分岐に名前で結ぶ。`in`・辞書表・選択子の再束縛・別ファイル・ヘルパ内の Tool は結べず不一致を出さないが、未結合の件数は JSON にも --explain にも出ない。分岐を try で包むと try 全体が共通部になり、他ツールの書き込みが読み取り専用ツールに付く誤警報が出た。AuthGap の 14 規則のうち reachscan が持つのは mcp / fastmcp デコレータ・lowlevel_v1・langchain・crewai・openai-agents・semantic-kernel で、lowlevel_v2・呼び出し形・gptme・autogpt・langroid・agno のメソッド・汎用 tools_list は無い。逆に pydantic_ai・autogen・LlamaIndex・DSPy・Swarm・MetaGPT・Marvin は AuthGap に無い。
