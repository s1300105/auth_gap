## 2. 書き方の共通の約束

- **値は下の表の字のとおりに書く**（全角・半角、括弧、中黒「・」、空白まで）。例: `違反（深さ 4 の外）` は全角の括弧、「深さ」と「4」と
  「の外」のあいだは半角の空白。
- **1 つのセルに改行を入れない**。区切りたいときは「／」（全角の斜線）を使う。
- **パスは木の根からの相対**で書く（`src/pkg/a.py:12`。`corpus/<tree>/` は付けない）。
- **行は `ファイル:行`**、範囲は `ファイル:始め-終わり`。同じファイルの続きは `:行` だけでもよい（例 `a.py:12 → :30`）。
- 空にする欄は**何も書かない**（「なし」「-」も書かない）。`ai_found` だけは、点検して新しく見つからなければ `なし` と書く。
- 分は**整数**（30 秒以上は切り上げ）。時刻は `HH:MM`（24 時間）。

### 3.3 `unknown_reason`（不明のときだけ）

- 形: `<類>: <説明>`（類の**直後に**半角の `:`、そのあと空白 1 つ。`類 : 説明` のようにコロンの前に空白を入れると、集計の道具が読めない）。
  説明には、決められない動作の**ファイル:行**と、何が決められないかを書く。`相手の API` の「の」と「API」のあいだは半角の空白。
- 類は 1 つ（19 節）:

| 類（この字のとおり） | 使うとき |
|---|---|
| `外の値` | 書き先・宛先・コマンド、またはライブラリの関数の動作が、木の外のライブラリの戻り値や実行時の外の状態で決まり、読み切れない |
| `相手の API` | 相手の API（`POST` の先、SDK の呼び出し）の意味が、文書にもコードにも無く、名前でもはっきりしない（名前がはっきり示すなら「API 名から」「関数名から」で決める） |
| `起動・初期化` | 起動の方法・初期化の場所が読み切れない（14.4） |
| `動的な呼び出し` | `getattr(obj, name)()`・プラグインの読み込み・木の外のライブラリが木の中の関数を呼び戻す形などで、呼び出し先・呼ばれる時点が決まらない |
| `手引きで決まらない` | 手引きのどの規則にも当てはまらない（22 節） |
| `その他` | 上のどれでもない（説明を必ず書く） |

- `打ち切り` は**使わない**（解析器の打ち切りの類。実態調査は解析器を見ない）。
- 手引き 22 節の事例（仮の扱いが無く、手引きで決まらない点）は、この説明に書く。類を別にしたが、手引きで決まらない点も
  重なっていたら、その事例も説明に書く（類をどちらにするかの規則は手引きに無い。O48 (7)）。
- 公式の文書を開いても決まらなかったなら、開いた文書の URL も説明に入れる（19）。
- 例: `相手の API: src/app/client.py:88 の POST /v2/items/{item_id}/sync が更新か照会かが、相手の文書（https://docs.example.com/api の v2 の一覧）にもコードにも無く、名前の sync でも決まらない`
- 例: `手引きで決まらない: 別のツール set_target が書いたモジュール水準の _TARGET（app/state.py:5）を、このツールの書き先（app/tools.py:40）をモデルが決める値とするか決まらない（FAQ Q35。仮の扱いは無い）`

### 3.4 `evidence`

**第三者がその答えを確かめる手がかりを、答えごとに 1 つだけ書く**（D89）。判定者が 1 人なので、これが判定の信頼性の支えです
（D67 の 4）。AI が示した行は、自分で開いて確かめたものだけを書く。

| 答え | 書くこと | 形 |
|---|---|---|
| `違反`・`違反（深さ 4 の外）` | **道筋**: 本体から反する行まで | 各段の `ファイル:行` を ` → ` でつなぎ、最後に何をするかを一言。同じファイルの続きは `:行` だけでよい |
| `違反でない`・`不明` | **読んだ範囲**（18.4「「反する動作は無い」でも、読んだ範囲を書く」） | `読んだ範囲: ` に続けて、読んだ関数の `ファイル:始め-終わり` を「、」で並べる（届く分岐だけ読んだ関数は、読んだ行の範囲）。関数名・深さは書かなくてよい |
| `対象外` | **理由** | 1 文（宣言の行と、なぜツールの宣言でないか） |

- **文書で決めたとき**（相手の API の意味・知られていないライブラリの関数を、公式の文書を開いて決めた）だけ、その URL を最後に
  「／」で区切って添える（手引き 19 は、文書で確かめたら URL を書くとする）。`POST` の意味を API 名で決めたときは「API 名から」と
  添える（手引き 15.1 の `POST` の行がそう書くよう求め、件数を報告する）。
- **書かないもの**（D89。考えることで、記録しない）: 登録の 1 文、反しない理由・根拠の節、木の外の呼び出し、読まなかった枝・
  深さ 4 で止めた関数、確かめたこと（デコレータ・middleware の有無、ログの設定の検索、届かない行）。確かめる手順そのものは
  省かない（`02_steps.md`）。
- 「読んだ範囲」は、確かめの道具が `違反でない`・`不明` の行で探す語です。この字で始めてください。

良い例（`違反`。`06_example.md` の例題）:

> notes_server.py:48 search_notes → :38 _search → :30 _remember_query: open(~/.notes_mcp/history.jsonl, "a") に時刻と検索語を追記

良い例（`違反でない`。例題の list_tags）:

> 読んだ範囲: notes_server.py:52-55、:19-21、:23-26

良い例（`不明`。架空）:

> 読んだ範囲: app/server.py:31-41、app/client.py:20-35、:80-95、:100-120

良い例（`違反でない`。文書で決めた。架空）:

> 読んだ範囲: app/server.py:20-44、app/search.py:10-60／https://docs.example.com/api/search

良い例（`対象外`。架空）:

> app/settings.py:12 の辞書 DEFAULT_ANNOTATIONS は設定の見本で、どのサーバにも登録されない

悪い例:

- 「open で書いているので違反」（行が無い。第三者が確かめられない）
- 「特に書き込みは無い」（読んだ範囲が無い）
- 「AI によると POST は照会」（AI の答えを写している。開いた文書の URL が無い）

## 5. 表の保存（表計算のソフトの注意）

- **どのソフトでも**: `t_start`・`t_end` の列は、入力の前に書式を「文字列（テキスト）」にするか、`'14:05` のように先頭に `'` を
  付けて入力する（そうしないと時刻の値に変わり、`14:05:00` で書き出されることがある。確かめの道具は秒の付いた時刻を誤りにする）。
- **Excel**: 「名前を付けて保存」で**「CSV UTF-8（コンマ区切り）」**を選ぶ（ただの「CSV（コンマ区切り）」は Shift-JIS になり、
  確かめの道具が読めない）。
- **Numbers**: 「書き出す → CSV」で、テキストエンコーディングを **Unicode (UTF-8)** にする。
- **Google スプレッドシート**: 「ファイル → ダウンロード → カンマ区切り形式（.csv）」（UTF-8 になる）。ダウンロードしたファイルで
  `practice/survey_practice.csv` を置き換える。
- セルの先頭を `=`・`+`・`-`・`@` にしない（式として読まれる）。
- 見出しの行と欄の順を変えない。表の上に行を足さない（道具が読めなくなる）。
- **結果の欄で並べ替えたり絞り込んだりしない**（手引き 21 の 2: 判定の途中で集計を見ることに当たる）。
- 保存したら、テキストエディタで開いて、セルの中に改行が入っていないか、`t_start` が `HH:MM` のままかを見る。**テキストエディタで
  直接書き直さない**（セルの中の `,` を `"` で囲み忘れると欄がずれる。直すのは表計算のソフトで）。

## 6. 確かめの道具

```bash
cd ~/Project/research/Master_Project/auth_gap
```

- 行ごとに「よい」「誤り: …」「注意: …」「まだ判定していない（飛ばした）」が出ます。**誤り**は直します。表の中だけで確かめられる
  もの（語彙・答えごとの欄・`違反でない`／`不明` の `evidence` の「読んだ範囲」・`違反` の `evidence` の `ファイル:行`・`その他:`／`不明:`・

  として出ます。**道具では確かめられないもの**（仮の扱いと翻訳の `note`、`note` と `evidence` の中身、`unknown_reason` の説明に `ファイル:行` があるか）は、自分で 3.3〜3.5 と見比べます。**注意**は、
  合っていれば直さなくてよい（例: `minutes` と時刻の差が 2 分より大きい。休憩を `t_break` に入れ忘れていないかを見る）。

  表計算のソフトで開いて保存し直してから、もう一度かけます。
- 道具が確かめるのは**書き方だけ**です（値が語彙の中か、答えごとの必須・空の欄、時間の形と計算）。判定の中身は確かめません。
