## 1.1 repo を更新し、木を取る

この手順書では、repo の根（`auth_gap/`）を `~/Project/research/Master_Project/auth_gap` とします（自分の場所に読み替える）。**コマンドはすべて repo の根で打ちます。**

```bash
cd ~/Project/research/Master_Project/auth_gap
git pull
```

- 出力の最後に、`evidence/practice_survey/manual/` などの新しいファイルが並べば最新です。`git log` の**本文**は読まないでください（1.4）。

仮想環境がまだ無ければ作ります（あれば飛ばす）:

```bash
uv venv .venv --python 3.10
uv pip install --python .venv/bin/python -r requirements.txt
```

練習の 4 木（W-01・T-01〜T-03）を取ります:

```bash
.venv/bin/python scripts/fetch_corpus.py --spec evidence/practice_survey/fetch_spec_survey_practice.json
git restore docs/frame.csv docs/fetch_failures.md
```

- 1 行目は木を `corpus/` の下に取り、指定の commit（SHA）と一致するかを確かめます。2 行目は、取得の道具が書き換える記録の
  ファイルを元に戻します（練習では使わない）。
- **手元に出るのは一部のファイルだけ**です（`.py`・`.toml`・`.txt`・`.lock`・`.json`・`.cfg`。部分クローンと sparse checkout）。
  `README.md`・`*.yaml`・`*.ini`・`logging.conf` などは手元に無くても木の中にあります。木の全部のファイルの名前は
  `git -C corpus/<tree> ls-tree -r --name-only HEAD`、手元に無いファイルの中身は `git -C corpus/<tree> show HEAD:<パス>` で読めます
  （その場で取ってくるのでネットワークが要る）。手元に無いファイルも木の中として扱います（`02_steps.md` の段 5 の 3）。
- 確かめ:

  ```bash
  ls -d corpus/v4-andrewbolster__mcp.bolster.online corpus/v4-bogacsmz__deja corpus/v4-aukern__scout-api corpus/v4-adrmarabuco__mcp-trading-view
  ```

  4 行とも出れば成功です。

**うまくいかないとき**

| 症状 | すること |
|---|---|
| `fetch_corpus.py` が SHA の不一致・取得の失敗を出す | そのまま進まず、出力を本記録者に送る（別の commit の木で判定すると答えがずれる） |
| `git restore` が「変更が無い」と言う | 問題なし（取得の道具が書き換えなかった） |
| `ls` で一部の木が無い | `fetch_corpus.py` をもう一度走らせる。それでも無ければ出力を送る |

**木の中のコードは実行しない**でください（`pip install -e`・サーバの起動・テストの実行）。読むだけです（手引き 19: 手元で動かして
確かめたものは「確かめた」に入らない）。

## 1.2 作業用のフォルダと表を用意する

repo の根に作業用のフォルダ `practice/` を作り、記録の表を写します（作ってあれば飛ばす）:

```bash
mkdir -p practice
cp evidence/practice_survey/survey_practice.csv practice/
ls practice
```

できあがりの形（`ls practice` で `survey_practice.csv`）:

```
auth_gap/                          ← repo の根（コマンドはここで打つ）
├── practice/                      ← 練習の作業フォルダ（自分で書くのはここだけ）
│   └── survey_practice.csv        ← 記録の表（4 行。03_record.md）。記録はここだけ
├── evidence/practice_survey/      ← 配った材料（書き換えない）
└── corpus/                        ← 判定する木（1.1 で取ったもの）
```

- `practice/` は `.gitignore` に入れてあるので、`git status` に出ず、`git pull` ともぶつかりません。`git add` もしないでください
  （公開の repo に入ります）。送るものは `05_practice.md` の 5.7。
- **表に書くのは段 9 の `outcome` と `evidence` だけです**（D90。練習も本番も）。手順書の段 0〜8 とチェックリストは考えることの一覧で、
  書き残しません。時間も記録しません。前に写した表（時間・ラベル・メモの欄があるもの）は、何も書いていなければ写し直してかまい
  ません（`cp` をもう一度打つ）。書いてあればそのまま使えます（増えた欄は空のままでよい。確かめの道具は見ない）。
  前に写した `practice/worksheets/`・`practice/ai_logs/` は使わないので、消してかまいません。
- 配った表（`evidence/practice_survey/survey_practice.csv`）など、git が追跡しているファイルは書き換えません。
- 表を開くソフトの保存の注意は `03_record.md` の 4 節（Excel は「CSV UTF-8」で保存）。
- 確かめの道具がこの表を読めるかを、まだ何も書いていない状態で確かめておきます:

  ```bash
  .venv/bin/python scripts/check_survey_practice.py practice/survey_practice.csv
  ```

  4 行とも「まだ判定していない（飛ばした）」、最後に「誤りなし」と出れば成功です。

## 1.3 エディタを用意する

### 1.3.0 VS Code と Python の拡張機能

1. VS Code を入れ、拡張機能（`Ctrl+Shift+X` / `Cmd+Shift+X`）で **Python**（作者 Microsoft。Pylance も一緒に入る）を入れる。
2. 木を開いたときに「このフォルダーの作成者を信頼しますか」と聞かれたら、**「信頼しない」（制限モード）**を選ぶ。木には
   `.vscode/` の設定や作業の定義（`.json`）が入っていることがあり、信頼すると木の中のものが動きうる（木の中のコードは実行しない。
   1.1）。制限モードでは Pylance の一部（定義へ移動など）が効かないことがあるが、木の中の検索で足りる（`02_steps.md` の段 4 の 3）。
3. 端末から `code` で開けるようにする（Mac は VS Code のコマンドパレットで「Shell Command: Install 'code' command in PATH」）。

### 1.3.1 AI を切る（手引き 21 の 6「判定の間は、エディタに組み込まれた AI の機能を切る」）

VS Code の場合:

1. 左の「拡張機能」（`Ctrl+Shift+X` / `Cmd+Shift+X`）を開く。
2. 「GitHub Copilot」「GitHub Copilot Chat」など AI の拡張機能ごとに、歯車 →「無効にする」（全体で切るか、練習の木の窓では
   「無効にする（ワークスペース）」）。
3. 設定（`Ctrl+,` / `Cmd+,`）で `copilot` と `chat` を検索し、提案（inline suggestions）やチャットの機能が有効になっていないかを見る。
4. Cursor・Windsurf など AI が組み込まれたエディタは使わない（使うなら AI の機能をすべて切る）。
