# 実態調査の形の判定の手順書（練習用・2026-10-09 版）

この手順書は、**実態調査の形の判定を、横に開いて上から順になぞりながら行う**ためのものです。練習（ロードマップ A2）で使い、本番の
手順書（封の前に段階 B2 で作る）の下書きも兼ねます。

- 判定の規則の正本は手引きの下書き `docs/drafts/final_judging_guide_draft.md`（未承認。封の前に変わりうる）と決定（`docs/decisions.md`）
  です。**この手順書は、手引きの規則を 1 件を判定する順に並べ直し、記録の書き方と練習の段取りを足したもの**で、規則を足しません（下の 3 節の
  印を付けたところを除く）。**手引きと食い違ったら手引きを採り、食い違いを教えてください。**
- 実態調査（D82・D85）: D1（`readOnlyHint: true`）を宣言したツールについて、**解析器の出力を見ずに**、ツールの本体から深さ 4 まで読み、
  D1 に反する動作に届くかを決める。答えは `違反` / `違反でない` / `不明` / `対象外`（と、別に数える `違反（深さ 4 の外）`）。手順は見落としの
  判定（手引き 18 節）と同じ（D82）。

## 2. 1 件の流れ（地図）

```
段 0 準備（時計の外）
段 1 名簿の行を読む ………… 時計を動かす（t_start）
段 2 登録と本体 …………… 対象外なら → 段 9
段 3 本体（深さ 0） ………… デコレータの wrapper・middleware も
段 4 深さ 4 まで ………… 道筋の表（D 節）
段 5 環境を変えうる行 ……… 候補の表（F 節）・ログの設定
段 6 動作ごとに …………… 届くか・条件・反するか・書き込み先
段 7 答え …………………… 違反 / 違反でない / 不明 / 対象外 / 違反（深さ 4 の外）
段 8 20〜30 分の目安 ……… 不明の理由
段 9 記録 …………………… ラップ（t_noai）
段 10 AI の点検（任意） …… ここでだけ AI を使う
段 11 仕上げ ……………… 時計を止める（t_end・minutes）、確かめの道具
```

## 3. 印の意味

| 【手引きに無い】 | 手引きにも決定にも規則が無い。O48 に、封の前に学生が決める点として書いた。ここに書いたのは**練習のための仮の扱い** | 仮の扱いで進め、それが結論にかかわったら `note` に「O48 (n) の仮の扱い: …」と書く。仮の扱いでも決まらなければ、手引き 22 のとおり `不明`（`unknown_reason` は「手引きで決まらない: …」） |
| （15.1）など | 手引きの節の番号 | 迷ったらその節を読む |
| D82 など | `docs/decisions.md` の決定の番号 | |

## 4. 用語

| 語 | 意味 |
|---|---|
| 木 | 判定するリポジトリ（`corpus/<tree>/`） |
| 名簿 | 宣言を見つけてツールに結びつけた一覧（`scripts/survey_roster.py`。解析器を使わない。D85） |
| 本体 | 判定するツールの関数（`def` から関数の終わりまで）。深さ 0 |
| 深さ | 本体から何回呼び出しをたどったか。本体 = 0、本体が呼ぶ木の中の関数 = 1 …（解析器の数え方。18.2 の 2） |
| 木の中 / 木の外 | 木の中に定義がある関数 / pip で入るライブラリの関数 |
| 道筋 | 本体から、ある行までの呼び出しの連なり |
| 環境を変える | 呼び出しの後に残る何かを変える（ホストのファイル・DB・相手のサーバの状態・残る設定）。D1 の問い（15.1） |
| 届く | ツールが呼ばれたとき、その行が実行される道が 1 つでもある（14.1） |
| 条件の種類 | どんなときに届く・環境が変わるか（14.3 の 7 種類） |
| 書き込み先の種類 | 何を変えるか（16.1 の 8 種類）。違反の軽重を表すラベルで、正誤には持ち込まない |
| wrapper | デコレータが本体を包んだ関数。深さに数えないが中身は読む |
| 対象外 | 名簿の件がツールの宣言ではない（D85） |

## 6. どの段にも掛かる約束

| 約束 | 出典 |
|---|---|
| **原理を字義どおりに当てる**。自分の感覚で「これくらいは違反と言えない」と判断しない。問いは「宣言は正しいか」で「危ないか」ではない。読み取り専用のツールがログファイルに 1 行足すのも違反 | 手引き 11.3（D67 の 1） |
| **軽重はラベル（書き込み先の種類）で表し、正誤に持ち込まない** | 11.3・16 |
| **分からないものを黙って違反・違反でないに倒さない**。決められなければ `不明` にして理由を書く。ただし調べれば分かるものは不明にしない | 19、CLAUDE.md 規則 4 |
| 判定するのは**コードの動作**で、説明（docstring・ツールの説明文・解析器の説明）ではない | 11.2 |
| **してはいけないこと**: 迷った件を黙って倒す／AI に判定させる・AI の答えを確かめずに記録する・宣言の値や解析器の答えを AI に渡す／判定の途中で集計を見る（結果の欄を数える・並べ替える・絞り込む）／結果を見て判定を止める（止めてよい理由は時間だけ） | 事前登録の下書き (h)、21 の 2 |
| 実態調査の数は**下限**: 1 サーバ 1 ツールだけ、深さ 4 まで、プロセスのメモリの中の状態は数えない、木の外のライブラリの中は読まない | D82 の 6、事前登録の下書き (f2) |
| **迷った件は印を付けて翌日に見直す**。見直したら `note` に「見直し: N 分、前 → 新（理由）、日付」 | 21 の 4・12.3 |
| 判定の根拠（ファイルと行の連なり）は全件残して公開する。2 人目の判定者がいない分、`evidence` が信頼性の支え | 事前登録の下書き (e)、手順 H（D67 の 4） |
