## 2. 書き方の共通の約束

- **値は下の表の字のとおりに書く**（全角・半角、括弧、中黒「・」、空白まで）。例: `違反（深さ 4 の外）` は全角の括弧、「深さ」と「4」と
  「の外」のあいだは半角の空白。
- **1 つのセルに改行を入れない**。区切りたいときは「／」（全角の斜線）を使う。
- **パスは木の根からの相対**で書く（`src/pkg/a.py:12`。`corpus/<tree>/` は付けない）。
- **行は `ファイル:行`**、範囲は `ファイル:始め-終わり`。同じファイルの続きは `:行` だけでもよい（例 `a.py:12 → :30`）。
- 空にする欄は**何も書かない**（「なし」「-」も書かない）。`ai_found` だけは、点検して新しく見つからなければ `なし` と書く。
- 分は**整数**（30 秒以上は切り上げ）。時刻は `HH:MM`（24 時間）。

### 3.3 `unknown_reason`（不明のときだけ）

- 形: `<類>: <説明>`（類の**直後に**半角の `:`、そのあと空白 1 つ。`類 : 説明` のようにコロンの前に空白を入れると、集計の道具が読めない）。
  説明には、決められない動作の**ファイル:行**と、何が決められないかを書く。`相手の API` の「の」と「API」のあいだは半角の空白。
- 類は 1 つ（19 節）:

| 類（この字のとおり） | 使うとき |
|---|---|
| `外の値` | 書き先・宛先・コマンド、またはライブラリの関数の動作が、木の外のライブラリの戻り値や実行時の外の状態で決まり、読み切れない |
| `相手の API` | 相手の API（`POST` の先、SDK の呼び出し）の意味が、文書にもコードにも無い |
| `起動・初期化` | 起動の方法・初期化の場所が読み切れない（14.4） |
| `動的な呼び出し` | `getattr(obj, name)()`・プラグインの読み込み・木の外のライブラリが木の中の関数を呼び戻す形などで、呼び出し先・呼ばれる時点が決まらない |
| `手引きで決まらない` | 手引きのどの規則にも当てはまらない（22 節） |
| `その他` | 上のどれでもない（説明を必ず書く） |

- `打ち切り` は**使わない**（解析器の打ち切りの類。実態調査は解析器を見ない）。
- 例: `相手の API: src/app/client.py:88 の POST /v2/items/query が作成か照会かが、相手の文書（https://example.com/api の該当ページ）にもコードにも無い`
- 例: `手引きで決まらない: 1 つの宣言 READ_ONLY を同じ関数の中の 3 つのツールが使い、どれを判定するか決まらない（app/tools.py:12）`

### 3.4 `evidence`

**判定を見ていない第三者が、その行を開けば同じ結論に着けるように書く**（手順 H）。2 人目の判定者がいない分、これが判定の信頼性の
支えになります（D67 の 4）。AI が示した行は、自分で開いて確かめたものだけを書く。

書く順（「／」で区切る）:

1. **登録**（1 文）: どの行の宣言が、どのサーバのどのツールを登録しているか。
2. **道筋**: 本体から反する動作まで（`違反` のとき）、または読んだ全体（`違反でない`・`不明` のとき）。各段を `ファイル:行` で書き、
   `→` でつなぎ、括弧に深さと、その段で何が起きるかを書く。条件があれば「条件: …」。
3. **反する理由・反しない理由**: 反する動作なら何をどこに書くか。反しないなら、なぜ反しないか（「HTTP は :24 の GET だけ」
   「ログは :10 の設定で標準エラー」など）。外の文書で決めたら URL、名前で決めたら「関数名から」「API 名から」。
4. **読んだ範囲**: `読んだ範囲: a.py:1-60（深さ 0・1）、b.py:10-45（深さ 2）…`。**どの答えでも書く**（18.4「「反する動作は無い」でも、読んだ
   範囲を書く」）。`違反でない`・`不明` では必ず。最初の違反で止めたら、止めたところまでの範囲。
5. **確かめたこと**: ログの設定の検索（語と範囲と結果）、届かないと決めた行とその理由（「:15 の makedirs はモジュールの読み込み時で
   届かない（14.4）」など）。

良い例（`違反`。`06_example.md` の例題）:

> 登録: notes_server.py:42 の宣言で :13 の FastMCP("notes") に search_notes を登録／道筋: notes_server.py:43-48 search_notes（深さ 0。:48 で
> _search(query, save_history)）→ :34-39 _search（深さ 1。条件: :37 save_history が真）→ :29-31 _remember_query（深さ 2）:30 open(STATE_DIR
> /history.jsonl, "a") で時刻と検索語を 1 行追記（STATE_DIR は :14 の ~/.notes_mcp）。このツールは history.jsonl を読み返さない／読んだ範囲:
> notes_server.py:1-48（深さ 0〜2。NotesClient.__init__ :19-21・search :23-26 は深さ 2）／確かめたこと: HTTP は :24 の GET だけ。ログの設定は
> :10 の basicConfig(level=INFO) だけで標準エラー（FileHandler|basicConfig|logger\.add|dictConfig をファイル全体で検索）。:15 の makedirs は
> モジュールの読み込み時で届かない（14.4）

良い例（`違反でない`）:

> 登録: notes_server.py:51 の宣言で :13 の FastMCP("notes") に list_tags を登録／読んだ範囲: notes_server.py:52-55（深さ 0）、:19-21
> NotesClient.__init__（深さ 1、:54 の構築）、:23-26 NotesClient.search（深さ 1、:55）／反しない理由: HTTP は :24 の GET だけ（15.1 の GET の行）。
> 書き込み・DB・プロセスの起動は無い／確かめたこと: このツールはログを出さない。ログの設定は :10 で標準エラー。:15 の makedirs はモジュールの
> 読み込み時で届かない（14.4）

到達は決められないが、届いたとしても反しない動作は、`違反でない` にし、`evidence` に「到達は決められないが、反しない」と書く
（D86 の 10）。

悪い例:

- 「open で書いているので違反」（どの行か、どう届くかが無い）

## 5. 表の保存（表計算のソフトの注意）

- **Excel**: 「名前を付けて保存」で**「CSV UTF-8（コンマ区切り）」**を選ぶ（ただの「CSV（コンマ区切り）」は Shift-JIS になり、
  確かめの道具が読めない）。`t_start`・`t_end` の列は、入力の前に書式を「文字列」にするか、`'14:05` のように先頭に `'` を付けて
  入力する（そうしないと `14:05:00` に変わる）。
- **Numbers**: 「書き出す → CSV」で、テキストエンコーディングを **Unicode (UTF-8)** にする。
- **Google スプレッドシート**: 「ファイル → ダウンロード → カンマ区切り形式（.csv）」（UTF-8 になる）。ダウンロードしたファイルで
  `~/authgap_practice/survey_practice.csv` を置き換える。
- セルの先頭を `=`・`+`・`-`・`@` にしない（式として読まれる）。
- 見出しの行と欄の順を変えない。表の上に行を足さない（道具が読めなくなる）。
- **結果の欄で並べ替えたり絞り込んだりしない**（手引き 21 の 2: 判定の途中で集計を見ることに当たる）。
- 保存したら、テキストエディタで開いて、セルの中に改行が入っていないか、`t_start` が `HH:MM` のままかを見る。

## 6. 確かめの道具

```bash
cd ~/research/auth_gap
.venv/bin/python scripts/check_survey_practice.py ~/authgap_practice/survey_practice.csv
```

- 行ごとに「よい」「誤り: …」「注意: …」「まだ判定していない（飛ばした）」が出ます。**誤り**は直します（直したことを `note` に
  「確かめの道具で直した: …」）。**注意**は、合っていれば直さなくてよい（例: `minutes` と時刻の差が 2 分より大きい）。
- 道具が確かめるのは**書き方だけ**です（値が語彙の中か、答えごとの必須・空の欄、時間の形と計算）。判定の中身は確かめません。
