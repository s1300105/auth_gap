## 2. 書き方の共通の約束

- **値は下の表の字のとおりに書く**（全角・半角、括弧、中黒「・」、空白まで）。例: `違反（深さ 4 の外）` は全角の括弧、「深さ」と「4」と
  「の外」のあいだは半角の空白。
- **1 つのセルに改行を入れない**。区切りたいときは「／」（全角の斜線）を使う。
- **パスは木の根からの相対**で書く（`src/pkg/a.py:12`。`corpus/<tree>/` は付けない）。
- **行は `ファイル:行`**、範囲は `ファイル:始め-終わり`。同じファイルの続きは `:行` だけでもよい（例 `a.py:12 → :30`）。
- 空にする欄は**何も書かない**（「なし」「-」も書かない）。`ai_found` だけは、点検して新しく見つからなければ `なし` と書く。
- 分は**整数**（30 秒以上は切り上げ）。時刻は `HH:MM`（24 時間）。

## 3. 欄ごとの書き方

### 3.1 `outcome`

| 値（この字のとおり） | いつ |
|---|---|
| `違反` | 深さ 4 の中に、届いて D1 に反する動作がある |
| `違反（深さ 4 の外）` | 深さ 4 の中に反する動作が無く、深さ 4 より奥で偶然見つけた反する動作がある（深さ 4 の中に決められない動作があっても。18.3） |
| `違反でない` | 反しうる動作が無い、または全部「届かない」か「反しない」（届くかを決められなくても、届いたとしても反しない動作はここ。D86 の 10） |
| `不明` | 深さ 4 の中に反する動作は無く、違反になりうるのに決められない動作があり、深さ 4 より奥の違反も見つけていない |
| `対象外` | 名簿の件がツールの宣言ではない（D85） |

### 3.3 `unknown_reason`（不明のときだけ）

- 形: `<類>: <説明>`（類の**直後に**半角の `:`、そのあと空白 1 つ。`類 : 説明` のようにコロンの前に空白を入れると、集計の道具が読めない）。
  説明には、決められない動作の**ファイル:行**と、何が決められないかを書く。`相手の API` の「の」と「API」のあいだは半角の空白。
- 類は 1 つ（19 節）:

| 類（この字のとおり） | 使うとき |
|---|---|
| `外の値` | 書き先・宛先・コマンド、またはライブラリの関数の動作が、木の外のライブラリの戻り値や実行時の外の状態で決まり、読み切れない |
| `相手の API` | 相手の API（`POST` の先、SDK の呼び出し）の意味が、文書にもコードにも無く、名前でもはっきりしない（名前がはっきり示すなら「API 名から」「関数名から」で決める） |
| `起動・初期化` | 起動の方法・初期化の場所が読み切れない（14.4） |
| `動的な呼び出し` | `getattr(obj, name)()`・プラグインの読み込み・木の外のライブラリが木の中の関数を呼び戻す形などで、呼び出し先・呼ばれる時点が決まらない |
| `手引きで決まらない` | 手引きのどの規則にも当てはまらない（22 節） |
| `その他` | 上のどれでもない（説明を必ず書く） |

- `打ち切り` は**使わない**（解析器の打ち切りの類。実態調査は解析器を見ない）。
- 例: `相手の API: src/app/client.py:88 の POST /v2/items/{item_id}/sync が更新か照会かが、相手の文書（https://docs.example.com/api の v2 の一覧）にもコードにも無く、名前の sync でも決まらない`
- 例: `手引きで決まらない: 別のツール set_target が書いたモジュール水準の _TARGET（app/state.py:5）を、このツールの書き先（app/tools.py:40）をモデルが決める値とするか決まらない（FAQ Q35。仮の扱いは無い）`

### 3.4 `evidence`

**判定を見ていない第三者が、その行を開けば同じ結論に着けるように書く**（手順 H）。2 人目の判定者がいない分、これが判定の信頼性の
支えになります（D67 の 4）。AI が示した行は、自分で開いて確かめたものだけを書く。

書く順（「／」で区切る）。答えごとの順は下の良い例のとおり（`違反` は 1→2→4→5 で 3 は 2 の中に書く、`不明` は 1→2→3→4→5、
`違反でない` は 2 を書かず 1→4→3→5）:

1. **登録**（1 文）: どの行の宣言が、どのサーバのどのツールを登録しているか。
2. **道筋**（`違反`・`不明` のとき）: 本体から、反する動作か決められない動作まで。各段を `ファイル:行` で書き、`→` でつなぎ、
   括弧に深さと、その段で何が起きるかを書く。条件があれば「条件: …」。
3. **反する理由・反しない理由・決められない理由**: 反する動作なら何をどこに書くか。反しないなら、なぜ反しないか（「HTTP は :24 の
   GET だけ」「ログは :10 の設定で標準エラー」など）。外の文書で決めたら URL、名前で決めたら「関数名から」「API 名から」。
4. **読んだ範囲**: **どの答えでも書く**（18.4「「反する動作は無い」でも、読んだ範囲を書く」）。`違反でない`・`不明` では必ず。最初の
   違反で止めたら、止めたところまでの範囲。深さごとに、深さの間は全角の「；」で区切る（セルの区切りの「／」と混ぜない）:
   `読んだ範囲: 深さ 0: a.py:10-40 tool；深さ 1: a.py:50-70 f、b.py:5-30 g；深さ 2: c.py:12-40 h（:20 の if x の中だけ）；深さ 3: …；深さ 4: …`
   - 読まなかった枝があれば `読まなかった枝: a.py:22-35（理由）`（段 4 の 6）。
   - 深さ 4 の関数が呼ぶ先を読まなかったら `深さ 4 で止めた: d.py:95 i → j（深さ 5、読んでいない）`。
   - 木の外の呼び出しで環境を変えないと見たものは `木の外: a.py:31 httpx.get（GET）、b.py:12 json.loads`。
5. **確かめたこと**: ログの設定の検索（語と範囲と結果）、届かないと決めた行とその理由（「:15 の makedirs はモジュールの読み込み時で
   届かない（14.4）」など）、開いた文書の URL。

### 3.5 `note`

`note` は「迷ったとき」だけでなく、次の場面では**必ず**書きます。決まった書き出しを使い、「／」で区切ります（`その他:`・`不明:` は
**先頭**、ほかは順を問わない）。

| 場面 | 書き出し（この字で始める） | 例 |
|---|---|---|
| `write_target` が `その他・不明`（**先頭に書く**。16 節） | `その他:` か `不明:` | `その他: 別のプロセスとの受け渡しファイルの残りの削除` |
| 最初の違反で止めた（`stopped_early` = `はい`） | `最初の違反で止めた` | `最初の違反で止めた（深さ 2 まで読んだ）` |
| 止めない方針で、最初の違反が決まった時点（段 7 の 3） | `最初の違反:` | `最初の違反: 14 分（深さ 1 の a.py:40）` |
| 【手引きに無い O48 (n)】の仮の扱いで、答えかラベル（`write_target`・`condition_type`・`depth`）が決まった | `O48 (n) の仮の扱い:`（N の項目は `O48 (6) N<k> の仮の扱い:`） | `O48 (3) の仮の扱い: somelib の get_report は関数名から読み取り` |
| 仮の扱いが無く、手引き 22 節で `不明` にした | （`unknown_reason` に `手引きで決まらない: …` を書く。`note` には読めば何になるか） | `読めば 違反（初回）` |
| 時計が 20 分・30 分を過ぎた時点で、まだ答えが決まっていなかった（段 8） | `20 分:`・`30 分:` | `20 分: client.py の受け手を探していた／30 分: 決まった（31 分）` |
| 段 10 で AI に点検させた | `AI の前の判定:` | `AI の前の判定: 違反` |
| 英語の文書を機械翻訳した | `翻訳:` | `翻訳: DeepL（相手の API の文書）` |
| 深さ 4 の外の違反（主は深さ 4 の中の違反） | `深さ 4 の外:` | `深さ 4 の外: lib/a.py:90 の open(…, "w")（深さ 6）` |

| 1 件を日をまたいで中断した（`01_setup.md` の 1.6） | `中断:` | `中断: 10-12 の 17:40 に止め、10-13 の 9:10 に再開（段 4 の途中）` |
| 後で見直した（21 の 4・12.3） | `見直し:` | `見直し: 5 分、違反でない → 違反（ログの設定を見落としていた）、2026-10-12` |

### 3.6 AI の欄

## 5. 表の保存（表計算のソフトの注意）

- **どのソフトでも**: `t_start`・`t_end` の列は、入力の前に書式を「文字列（テキスト）」にするか、`'14:05` のように先頭に `'` を
  付けて入力する（そうしないと時刻の値に変わり、`14:05:00` で書き出されることがある。確かめの道具は秒の付いた時刻を誤りにする）。
- **Excel**: 「名前を付けて保存」で**「CSV UTF-8（コンマ区切り）」**を選ぶ（ただの「CSV（コンマ区切り）」は Shift-JIS になり、
  確かめの道具が読めない）。
- **Numbers**: 「書き出す → CSV」で、テキストエンコーディングを **Unicode (UTF-8)** にする。
- **Google スプレッドシート**: 「ファイル → ダウンロード → カンマ区切り形式（.csv）」（UTF-8 になる）。ダウンロードしたファイルで
  `~/authgap_practice/survey_practice.csv` を置き換える。
- セルの先頭を `=`・`+`・`-`・`@` にしない（式として読まれる）。
- 見出しの行と欄の順を変えない。表の上に行を足さない（道具が読めなくなる）。
- **結果の欄で並べ替えたり絞り込んだりしない**（手引き 21 の 2: 判定の途中で集計を見ることに当たる）。
- 保存したら、テキストエディタで開いて、セルの中に改行が入っていないか、`t_start` が `HH:MM` のままかを見る。**テキストエディタで
  直接書き直さない**（セルの中の `,` を `"` で囲み忘れると欄がずれる。直すのは表計算のソフトで）。

## 6. 確かめの道具

```bash
cd ~/research/auth_gap
.venv/bin/python scripts/check_survey_practice.py ~/authgap_practice/survey_practice.csv
```

- 行ごとに「よい」「誤り: …」「注意: …」「まだ判定していない（飛ばした）」が出ます。**誤り**は直します（直したことを `note` に
  「確かめの道具で直した: …」）。この章が「必ず」とする書き方のうち、表の中だけで確かめられるもの（語彙・答えごとの欄・
  `evidence` の「読んだ範囲」・`その他:`／`不明:`・`最初の違反で止めた`・`最初の違反:`・`AI の前の判定:`・`手引きで決まらない` の
  ときの `note`・`condition_type` の順・時刻の形）は「誤り」として
  出ます。**道具では確かめられないもの**（`20 分:`・`30 分:` のメモ、仮の扱いのメモ、`evidence` の読んだ範囲の区切りと中身）は、
  自分で 3.4・3.5 と見比べます。**注意**は、合っていれば直さなくて
  よい（例: `minutes` と時刻の差が 2 分より大きい。休憩を `t_break` に入れ忘れていないかを見る）。
- 欄の数が見出しと合わない行は「欄の数が見出しより多い／少ない」とだけ出ます（セルの中の `,` を `"` で囲んでいない、など）。
  表計算のソフトで開いて保存し直してから、もう一度かけます。
- 道具が確かめるのは**書き方だけ**です（値が語彙の中か、答えごとの必須・空の欄、時間の形と計算）。判定の中身は確かめません。
- 本番の表の確かめは、封の前（段階 B2）に `scripts/final_aggregate.py` に足します。
