## 1. 深さ（18.2 の 2「深さは解析器の数え方で数える」、D76、D86 の 16）

| 形 | 深さ |
|---|---|
| 本体 | 0 |
| 本体が呼ぶ木の中の関数 | 1（その先 2、3、4） |
| `Cls(...)`（構築） | `Cls.__init__` が 1 段 |
| `Thread(target=f)` | `f` が 1 段 |
| `asyncio.to_thread(f, …)`・`loop.run_in_executor(None, f, …)`・`Executor.submit(f, …)`・`Process(target=f)`・`functools.partial(f, …)` | `f` が 1 段（解析器は `Thread(target=)` と同じ表で扱う。O48 (2)） |
| デコレータの wrapper | 数えない（中身は読む。D86 の 16）。【手引きに無い】wrapper の本体は深さ 0 として扱い、wrapper が呼ぶ関数が 1 |
| 木の中の middleware・呼び戻しの関数 | 【手引きに無い】数えない（中身は読む。O48 (1) の仮の扱い） |
| 同じ関数に何度も届く | 【手引きに無い】いちばん浅い深さ |
| 木の外のライブラリ | 読まない（関数そのものが環境を変えるかだけを見る） |

- 読むのは深さ 4 まで。深さ 4 より奥（5 以上）を探しに行かない（18.3）。偶然見つけた奥の違反は `違反（深さ 4 の外）`（深さ 4 の中に違反が
  あれば `note`）。

## 2. D1 に反するか（15 の前書き、15.1）

**問い**: その動作は、呼び出しの後に残る何かを変えるか（ホストのファイル・DB・相手のサーバの状態・残る設定）。
**表の行と問いの文が違う答えを指すときは、表の行を採る**（15 の前書き。例: `GET` で送信・作成する API は、問いの文では変えているが、
`GET` の行で「反しない」）。

| 動作 | 反するか | 注意 |
|---|---|---|
| ファイルの書き込み・作成・削除・移動・権限の変更 | **反する** | ログ・キャッシュ・一時ファイル・ディレクトリの作成も含む。同じ呼び出しの中で作って消す一時ファイルも反する。軽重はラベルで表す |
| コードの実行（`eval`・`exec`） | 反する | |
| プロセスの起動 | コマンドをモデルが決められるなら反する。定数なら、そのコマンドが実際に何をするかを調べ、環境を変えるなら反する・変えないなら反しない・分からなければ不明。運用者が設定で決めるコマンドなら、既定値・設定の見本・文書で分かればそれで決め、分からなければ不明（類は `外の値`。D86） | |
| DB のデータ・スキーマの変更（`INSERT`・`UPDATE`・`DELETE`・`CREATE`・`DROP` など） | 反する | |
| DB に残る設定・保守（`PRAGMA journal_mode=WAL`・`VACUUM` など） | 反する | |
| DB の接続単位の設定・トランザクション（`BEGIN`・`COMMIT`・`PRAGMA foreign_keys=ON` など） | 反しない | 接続が閉じれば消える |
| DB の読み取り（`SELECT` など） | 反しない | |
| HTTP の `PUT`・`PATCH`・`DELETE` | 反する | |
| HTTP の `POST` | **相手の API の意味を調べて決める**: 作成・更新・削除なら反する、照会（検索 API・RPC の読み取り）なら反しない、分からなければ不明 | API 名で決めてよいのは、名前が作成・更新・削除（または照会）をはっきり示すときだけで、`evidence` に「API 名から」と書く（D86） |
| HTTP の `GET`・`HEAD`・`OPTIONS` | 反しない | |
| ファイルの読み取り | 反しない | |

**迷いやすい形**（15.1）:

| 形 | 答え |
|---|---|
| 標準出力・標準エラーへのログ | 反しない（ファイルではない）。`logging` の出力先がファイルなら反する。出力先の設定を確かめる |
| 子プロセスの標準入力への書き込み | それ自体はファイルを変えない。子プロセスの動作を全部数えて決める（E5） |
| クライアントへの通知（`ctx.info()`・`ctx.report_progress()`） | 反しない |
| プロセスのメモリの中に残る状態（モジュール水準の辞書・キャッシュ） | **反しない**（D76 の 2。論文では「数えていない」と範囲として書く。O47） |
| `sqlite3.connect` が無いファイルを作る | ファイルの作成として反する。条件つき（14.3 の「環境が変わるのは一部」の行） |
| 認証・トークン・ログインの `POST` | `POST` の行のとおり、相手の文書で決める。文書に無ければ不明 |
| 外のログ・エラー収集のサービスへの送信、syslog | `POST` の行と同じく、相手の API の意味で決める |
| 定数のコマンドに、モデルが引数・オプションを渡す（`git diff <path>` など） | モデルが書けるオプションに環境を変えるもの（`--output=` など）があれば反する |

**HTTP 以外で相手を変えるもの**【手引きに無い】: SDK の作成・更新・削除、gRPC、メール・メッセージの送信、キューへの投入、クラウドの
保存（`put_object` など）は、15.1 の表に行が無いので、問いの文「相手のサーバの状態を変えるか」で決め、意味が分からなければ不明
（`相手の API`）にする（O48 (3)）。

**プロセスのメモリ以外のプロセスの状態**【手引きに無い】: `os.environ` の書き換え・`os.chdir`・ログの設定の書き換えは、プロセスが終われば
消えるので、D76 の 2 と同じく数えない読み。起動して残る子プロセス（常駐するサーバ）は、15.1 のプロセスの起動の行で決める（O47 が未決）。

**木の外のライブラリの関数**（18.2 の 2）: 中は読まない。関数そのものが環境を変えるもの（`requests.put`・`open(…, "w")`・`shutil.rmtree`
など）は候補に入れる。知られていない関数は【手引きに無い】O48 (3) の仮の扱い（`02_steps.md` の段 4 の 5）。

## 3. 届くか（14）

**基本**（14.1）: そのツールが呼ばれたとき、その効果が起きる実行の道が 1 つでもあるか。毎回起きる必要はない。ツールが積んだもの・
始めたもの（キュー・スレッド・プロセス）を、呼び出しが返った後に別のスレッド・プロセスが書くときも届く。

**届かない形**（14.2）:

| 形 | 見分け方 |
|---|---|
| 起動時の初期化（lifespan・import 時） | 下の 14.4 の表 |
| 呼び出し先の取り違え | 呼んでいるのは別の関数・組み込みのメソッド（受け手の型で確かめる） |
| 死んだコード | 効果のある関数がツールの道筋からは呼ばれていない（CLI・テスト・スクリプトからだけ）。**木の中を検索して呼び出し元を全部見る** |
| 定数で閉じた枝 | `if False:`、`if DEBUG:`（`DEBUG = False` が定数で、どこでも書き換えない）。ただし運用者が書き換える前提の `config.py` の定数は閉じていない（`運用者の設定`。D76） |
| 必ず先に抜ける | 効果の前に必ず `return` / `raise` する |

**一度だけの初期化**（14.4）: ツールの道筋の途中に「一度だけ初期化する」形（`if _x is None: _init()`・`global _initialized`・
`@lru_cache`）があり、効果がその初期化の中にあるとき、**その初期化がツールの受付より前に必ず済んでいるか**で決める。

| 初期化を先に済ませている場所 | 届くか | 条件の種類 |
|---|---|---|
| `main()` の中だけ、または `if __name__ == "__main__":` の中だけ | **届く**（`fastmcp run file.py:mcp` などで `main()` を通らずに起動できる） | `起動の方法` |
| lifespan の中（`FastMCP(..., lifespan=…)` に渡した関数の中） | 届かない | — |
| モジュールの読み込み時（モジュールの一番上の文） | 届かない | — |
| `mcp` を包む部品の起動フックの中（`some_framework.build(mcp, on_startup=init)` など） | **届く** | `起動の方法`（D86） |
| どこで先に済ませるか読み切れない | 不明（`起動・初期化`） | — |

- lifespan が初期化を**必ず**済ませるか（例外で抜けたら受付が始まらないか、条件つきではないか）も見る。条件つきなら、条件が偽のときは
  届く。
- 初期化の後に `None` に戻す行（`_x = None`）がツールの受付の途中で走りうるなら、再び届く。`atexit` やテストの中は数えない（D76）。
- ツールの道筋が初期化を呼ばない（守りの `if` が無い）なら、そもそもその効果は道筋に無い。

**同じ呼び出しの中で作って消すもの**（14.5）: 届く。D1 では反する（15.1）。

## 4. 条件の種類（14.3）

**決め方**

1. 届く道に条件が無く、毎回環境が変わる → `なし`。
2. 届く道の上の条件（`if`・ループ・`try`）と、行が環境を変える条件（無いときだけ作る、など）を全部書き出す。空の入力・失敗・前提の
   崩れで効果の前に抜けるものは書き出さない（条件に数えない）。
3. 1 つずつ下の表で種類を決める。
4. 「かつ」で重なる → 全部を `;` で並べる（表の順）。「または」でつながる → 一番弱い道の 1 つだけ。
5. 1 つの条件が 2 つ以上の種類に読める → **1 つだけ**、表の上からの順で先のもの。`起動の方法` の位置の効果が最初の呼び出しでだけ起きる
   ときは、`初回` を重ねずに `起動の方法` だけ。
6. 条件が何で決まるか読み切れない → 決められない → 不明。

| `condition_type` | 条件の例 | (B) に数えるか | (C) に数えるか |
|---|---|---|---|
| `なし` | 毎回届く | 数える | 数える |
| `引数` | モデルが渡す引数の値による（`if output_file:`・`if mode == "save":`） | 数える | 数えない |
| `初回` | 初回だけ・キャッシュが無いときだけ（`if not os.path.exists(d): os.makedirs(d)`） | 数える | 数えない |
| `失敗・期限切れ` | トークンの更新、再試行、エラー時の後始末 | 数える | 数えない |
| `外部の状態` | ファイルが無いとき、相手が特定の応答を返したとき | 数える | 数えない |
| `運用者の設定` | 環境変数・設定ファイル・起動の引数で有効になる（設定の名前を `condition` に書く） | **数えない** | 数えない |
| `起動の方法` | 初期化が `main()` の中だけにあり、`main()` を通らない起動で届く（14.4） | **数えない** | 数えない |

（(A) は条件を問わない主の数、(B) は運用者が決める条件でしか届かないものを除いた数、(C) は条件なしで届くものだけの数。手引き 14.3 は
見落とし・不の中身の条件を「内訳だけ」とするが、**実態調査では (B)(C) を下限として併記する**（事前登録の下書き (f2)）。だから実態調査の
`condition_type` は併記の数を直接動かす。）

**迷いやすい条件の書き方**（14.3、D76・D86）:

| 形 | `condition_type` |
|---|---|
| 行は毎回実行されるが、環境が変わるのは一部（`makedirs(d, exist_ok=True)`・`CREATE TABLE IF NOT EXISTS`・`unlink(missing_ok=True)`） | 環境が変わる場合の条件（`初回` / `外部の状態`） |
| 行には毎回届くが、宣言に反するのが一部の値のときだけ | 反する場合の条件（既存のファイル → `外部の状態`、モデルの値 → `引数`） |
| 相手のサーバの応答しだいで起きる効果 | 応答だけで決まるなら `外部の状態`。モデルの引数でも起こせると読めるなら、「1 つだけ」の規則で `引数` |
| 空の入力・失敗・前提の崩れ（表が無い、認証が通らない）で、効果の前に抜ける | 条件に数えない（ほかに条件が無ければ `なし`） |
| 引数の既定値で効果が起きる（`save: bool = True`） | `なし`（引数を渡さなくても起きる） |
| 既定では起きるが、設定で止められる（`if not NO_CACHE:`・`if __debug__:`） | `運用者の設定` を書かない（運用者が何もしなくても届く） |
| ツールの登録そのものが設定しだい（`if ENABLE_X:` の中の `@mcp.tool`） | `運用者の設定` |
| 運用者が置く目印のファイル・OS・任意の依存・運用者が書き換える前提の `config.py` の定数で決まる | `運用者の設定`（`外部の状態` にしない） |
| 「または」でつながる条件（`if trace or os.environ.get(...)`） | 一番弱い道の条件だけ（この例では `引数`） |
| 「かつ」で重なる条件（認証の方式の設定 かつ トークンの期限切れ） | 全部を `;` で並べる（手引きの例は `運用者の設定;失敗・期限切れ`。練習では表の順の `失敗・期限切れ;運用者の設定` と書く。`03_record.md` の 3.2） |

**弱い順**（ラベルを選ぶとき。手順 G・D76）: `なし` → `引数` → `初回` → `失敗・期限切れ` → `外部の状態` → 運用者が決める条件（`運用者の設定`・
`起動の方法`）。【手引きに無い】「かつ」で重なった条件どうしは、その中の一番強いものの強さで比べる（重なった方が起きにくい）。

## 5. 書き込み先の種類（16）

**決め方**: 反する動作 1 つに 1 つ。下の表を**上から順に**当て、最初に当てはまったものを付ける。名前（`cache` など）ではなく動作で
決める。「読み返す」の主語は判定しているツールだけ（同じサーバの別のツールが読み返しても、読み返したことにしない。D76）。

| 順 | 種類 | 定義 | 例 |
|---|---|---|---|
| 1 | `相手側の状態` | NET の効果で、通信相手のサーバの状態を変える | 課題の更新、メッセージの投稿 |
| 2 | `データベース` | DB の行・スキーマ・DB に残る設定を変える | `UPDATE …`、`PRAGMA journal_mode=WAL` |
| 3 | `利用者のファイル` | 利用者（またはモデル）が指定した場所のファイル、または利用者の文書・データとして扱われるファイル | モデルが決めた `output_file` への書き出し、編集対象のファイルの上書き |
| 4 | `ログ` | 記録のためだけに書き、ツールの動作では読み返さない | ログファイル・監査ログ・トレースへの追記 |
| 5 | `一時ファイル` | 同じ呼び出しの中で作って消す、または OS の一時領域（`tempfile`、`/tmp`）に作る | `mkstemp` した受け渡し用のファイルとその削除 |
| 6 | `キャッシュ・状態の保存` | ツールの動作のために自分で保存し、後で読み返す | キャッシュ、トークン・セッションの保存、索引、初回に作る作業ディレクトリ・設定ファイル |
| 7 | `プロセスの起動・コードの実行` | プロセスの起動・コードの実行の違反 | モデルが決めたコマンドの起動、`eval` / `exec` |
| 8 | `その他・不明` | 上のどれにも当てはまらない、または決められない | |

**境界の例**（16.2）:

| 事例 | 付ける種類 |
|---|---|
| 別のプロセスと話すための受け渡しファイルのうち、前の呼び出しが残した応答ファイルの削除 | `その他・不明`（`note` の先頭に「その他:」） |
| 同じ受け渡しファイルのうち、同じ呼び出しの中で作って消すもの | `一時ファイル` |
| 初回に作るディレクトリ（作業ディレクトリ） | `キャッシュ・状態の保存` |
| OAuth のトークンをファイルに保存 | `キャッシュ・状態の保存` |
| ツール自身の設定ファイルを書き換える | ツールが自分で保存して読み返す状態なら `キャッシュ・状態の保存`、利用者が開いて直す設定なら `利用者のファイル`（D86） |
| 初回だけ `~/.app/` を作る | `キャッシュ・状態の保存` |
| 初回に作る作業ディレクトリで、中身を読み返さない | `キャッシュ・状態の保存`（D76） |
| 読み返さない記録 | 「いつ・何をした」を書く行だけ `ログ`。ほかは順 5 以降で決める（D76） |
| OS の一時領域（`tempfile`・`/tmp`）に置き、後で読み返す、または前の残りを消す | `一時ファイル`（D76。場所で決める） |
| 運用者が環境変数で決めた場所への書き込み | 中身で決める（場所を運用者が決めたことだけでは `利用者のファイル` にしない） |
| プロセスの起動・コードの実行の違反で、子が何を変えるか分かるとき | `プロセスの起動・コードの実行`（子が何を変えるかで順 2〜6 に当てない） |
| 活動ログ `log.md` への追記 | `ログ` |
| モデルが決めたパスへのエクスポート | `利用者のファイル` |
| SQLite のキャッシュ DB への書き込み | `データベース`（順 2 が順 6 より先） |

- 途中で境界の事例が出て決められないときは `その他・不明` にし、事例を `note` に書く。途中で定義を足さない（22）。`その他・不明` のときは
  `note` の先頭に「その他:」（どれにも当てはまらない）か「不明:」（決められない）を書く。何のファイルか分かっていて種類の表に無いだけの
  ものは「その他:」（D86）。

## 6. 答えの決め方（【実態調査の当てはめ】D82、18.2 の 5・7、18.3）

```
対象外か（段 2）── はい ──→ 対象外
   │いいえ
深さ 4 の中に、届いて反する動作があるか ── はい ──→ 違反（ラベルは下）
   │いいえ
届くか・反するかを決められない動作があるか ── はい ──→ 不明（理由の類は 7 節）
   │いいえ
深さ 4 より奥で偶然見つけた、届いて反する動作があるか ── はい ──→ 違反（深さ 4 の外）
   │いいえ
違反でない
```

- **ラベル**（違反のとき）: 反する動作が 1 つならその動作。複数なら条件の一番弱い動作（4 節の弱い順）。同じ強さなら最初に反すると分かった
  動作。**最初の違反で止めた**なら、止めた動作（`note` に「最初の違反で止めた（深さ N まで読んだ）」）。
- 深さ 4 の中と奥の両方に違反があれば `違反`（奥のものは `note`）。
- 到達は決められないが、届いたとしても反しない動作は、答えを動かさない（`違反でない` のまま。`evidence` に「到達は決められないが、反しない」。
  D86 の 10）。
- 【手引きに無い】深さ 4 の中の `不明` と、奥の違反が重なるときの優先は決まっていない（O48 (4)）。練習では `不明` にし、奥の違反を `note` に
  書く。

## 7. 不明の理由の類（19）

| 類 | 使うとき | 例 |
|---|---|---|
| `外の値` | 書き先・宛先・コマンドが、木の外のライブラリの戻り値や実行時の外部の状態で決まり、読み切れない。運用者が設定で決めるコマンドの動作が分からない（D86） | 書き先のパスがライブラリの関数の戻り値 |
| `相手の API` | 相手の API（`POST` の先など）の意味が、文書にもコードにも無い | `POST /v2/items/run` の意味が文書に無い |
| `起動・初期化` | 起動の方法・初期化の場所が読み切れない（14.4） | 初期化がどこで先に済むか分からない |
| `動的な呼び出し` | `getattr(obj, name)()`・プラグインの読み込み・木の外のライブラリが木の中の関数を呼び戻す形で、呼び出し先・呼ばれる時点が決まらない（D86） | 名前の文字列で関数を選ぶ |
| `手引きで決まらない` | 手引きのどの規則にも当てはまらない（22） | `手引きで決まらない: <事例>` |
| `その他` | 上のどれでもない（説明を必ず書く） | |

- 実態調査では `打ち切り` を使わない（解析器の打ち切りの類）。
- **不明にしてよいのは、20〜30 分を目安に調べても決められないとき**。調べれば分かるもの（開いていないファイルがある、相手の文書を
  開いていない）は不明にしない（19）。
- 「確かめた」と言えるのは、公式の文書かソースを自分で開けたときだけ（開いた URL かパスを `evidence` に書く）。手元で動かして確かめた
  ものは、確かめたことにしない（19）。
