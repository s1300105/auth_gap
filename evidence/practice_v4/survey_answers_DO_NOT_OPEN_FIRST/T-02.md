## 4. 意見が分かれうるところ

- 書き込み先: Redis への SET を、順 1 の「相手側の状態」（別のサーバの状態を通信で変える）と読む余地がある。用途から「キャッシュ・状態の保存」と読むこともありうるが、順 2 が先なのでデータベースとした。
- 条件: redis を任意の依存として `運用者の設定` を付けた（(B) に数えない）。本番では REDIS_URL を設定して arq の ArqQueueAdapter を使い（sources/dependencies.py:79-84）redis が入るのがふつうと見て、`引数` だけにする判定者もありうる。
- Redis の鍵は TTL 300 秒のメモリ上のキャッシュなので、D76 の 2（メモリの中の状態は数えない）に当たるとして反しないと読む余地がある。この判定では、メモリを除くのは自分のプロセスだけで、Redis は別のサーバの状態と読んだ。
- 埋め込みの POST（embedder.py:166、深さ 4）を API の文書の「Creates an embedding」から「作成」と読むと反する。その場合は redis が無い構成でも毎回届くので、手順 G の一番弱い条件で condition_type は なし、write_target は 相手側の状態、depth は 4 になる。
