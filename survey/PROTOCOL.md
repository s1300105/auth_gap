# 実態調査の判定の規則（PROTOCOL）

D1（`readOnlyHint: true`）を宣言したツールを 1 件ずつ読み、宣言に反する動作（呼び出しの後に残る何かを変える動作）に届くかを決める。

- **実態調査の判定は、この文書だけを見て行えるようにしてある**（D95）。答えを変える規則は全部ここに置いた（2026-10-13 に、初めに
  短くまとめたときに落とした規則を戻した。D95 の訂正）。
- 規則の出どころは、手引きの下書き（`docs/drafts/final_judging_guide_draft.md`。「手引き 14.4」はその節）と決定（`docs/decisions.md`
  の D の番号）。**この文書と手引きが食い違ったら、写し違いなので手引きを採る**（封の前ならこの文書を直し、封の後なら直さずに事前登録の §5 に
  逸脱として書く。手引き 22 の 5）。下の【仮】の扱いは手引きに無いので、この文書で決める。
- 練習の手順書と FAQ（`archive/practice_survey_manual/`。FAQ は `07_faq.md` の Q01〜Q59）は記録。作例を見たいときに読んでよい。
  食い違ったらこの文書を採る。
- 印:
  - **【仮 O48 (n)】**: 手引きにも決定にも規則が無く、今の仮の扱い（`docs/open_questions.md` の O48 の (n)）。封の前に学生が決める
    （10 節の 1）。それまではこの扱いで判定する。
  - **【規則なし】**: 手引きにも仮の扱いにも規則が無い（10 節の 2）。**それで答えが変わるなら、その点は「決められない」**（6 の 3。
    手引き 22）。答えが変わらなければ、読み方を決めて進む。
  - **【未決】**: まだ決めていない（10 節の 3）。
- 答えを変えない細部（どの順にファイルを開くか、など）は判定者の自由。ただし**確かめる手順**（呼び出し元の検索・受け手の型・
  一度だけの初期化の場所・ログの設定）は省かない（省くと、違反を見逃して `違反でない` にする向きに誤る）。

## 1. 何を判定するか

1. 判定するのは、名簿の行（`tool`・`roster_form`・`roster_relpath`・`roster_lineno`・`decl_lineno`）が指すツールの関数（**本体**）。

   | `roster_form` | 本体 |
   |---|---|
   | `decorator` | 名簿の行の関数（デコレータの中に宣言がある） |
   | `name` | 宣言を入れた名前（`RO = ToolAnnotations(...)`）を使うデコレータか `add_tool` の関数 |
   | `add_tool` | `add_tool(fn, ...)` の最初の引数の関数 |
   | `call_register` | `mcp.tool(annotations=…)(fn)` の `fn`（import をたどる）。束縛メソッド（`self.search`）ならそのクラスのメソッド、`functools.partial(f, …)`・`lambda` なら中で呼ぶ `f`。ループで登録するなら、名簿の行で登録される関数 |
   | `tool_ctor`（低水準のサーバ） | 振り分けの関数（`@server.call_tool()` のハンドラ。`serve()` の中の入れ子のこともある）のうち、そのツールの名前の分岐。`if name != "x": raise` のような `!=` の分岐も見る【仮 O48 (4)】 |
   | `dict_registry`（自前の表） | 表に入っている関数（`handler`・`func`・`function`・`fn`）【仮 O48 (4)】 |
   | `unmapped` | 判定者が読んで決める（D85 の 3）。1 つの宣言を複数のツールが使うなら、宣言を使うツールを定義の順に並べ、seed ⑦ の乱数で 1 つ選ぶ【仮 O48 (5)】 |

   - 宣言の行（`decl_lineno`）を開いて宣言を確かめる。行のずれ・条件つきの式の中などで確かめられなくても、判定を進める。
   - 宣言の付いた関数が名簿の `tool` と違えば、宣言の付いた方を判定する【仮 O48 (4)】。
   - 同じ名前のツールが木の別の場所にあっても、名簿の位置のものだけを判定する。
   - ツールが関数やクラスの中で定義されていれば（`def register(mcp): @mcp.tool(...) def x(): ...`）、外側の関数がどこから呼ばれて
     サーバに登録されるかを確かめる。
2. **対象外**: 名簿の件が、MCP のサーバに登録されるツールの宣言でない（設定や例として置いた辞書など、どのサーバにも登録されない）
   （D85）。
   - 登録が設定しだい（`if ENABLE_X:` の中の `@mcp.tool`）なら、登録されうるので対象外にしない（手引き 14.3）。取り付け（`mount`）が
     環境変数しだいの形も同じ【仮 O48 (4)】。
   - 登録されていれば、サーバを起動する行が木の中に見つからなくても判定する【仮 O48 (4)】。
   - MCP 以外の枠組みにだけ登録している →【規則なし】。本体から深さ 4 までふつうに読み、違反があれば `違反`、無ければ `不明`
     【仮 O48 (8)】。

## 2. 起点と読む範囲

1. **起点（深さ 0）**。次の中の文は、どれも深さ 0 として読む。
   - 本体。
   - 本体を包む、木の中で定義されたデコレータの wrapper（手引き 18.2 の 2、D86 の 16）。デコレータは下から掛かるので、`@mcp.tool`
     より上に付いたものは登録されず走らない。`mcp.tool(...)(fn)` の形なら `fn` の定義に付いたデコレータを見る。`functools.wraps` は
     名前を写すだけで、呼ばれるのは wrapper。wrapper が本体を呼ぶこと（`asyncio.to_thread(fn)` などを通しても）は段に数えず、
     wrapper が本体のほかに呼ぶ木の中の関数が深さ 1【仮 O48 (4)】。
   - サーバに付いた木の中の middleware（`FastMCP(..., middleware=[...])` のクラスの `on_call_tool` など）と、木の外の middleware に
     渡した木の中の関数（呼び戻し）。サーバを別のサーバに `mount()` しているなら、取り付け先の親のサーバのものも【仮 O48 (1)】。
     親の middleware にだけある違反も違反に数える【仮 O48 (4)】。
   - 低水準のサーバ・自前の表（1 の 1）では、振り分けの関数の中で、分岐の前に必ず走る共通の処理（`audit(name, args)` など）。
     ほかのツールの名前の分岐は読まない【仮 O48 (4)】。
2. **ツールの入力**（入力のスキーマになる引数）はモデルが決める値で、**取りうる値の全体**で考える（手引き 11.3 の原理 3。`mode` に
   `"w"` を渡せば書ける、など）。枠組みが入れる引数（`ctx: Context` など）はモデルが決めない【仮 O48 (4)】。
3. **深さ 4 まで**読む。木の中の関数に 1 回降りるごとに 1 段。深さ 4 の関数の中身は読み、その先（深さ 5）は探しに行かない
   （手引き 18.2 の 2、18.3）。ライブラリの関数と値の変換（`os.path.join` など）は段を使わない。動作の深さは、その行が書かれている
   関数の深さ。
4. **深さの数え方**（手引き 18.2 の 2「深さは解析器の数え方で数える」）:

   | 形 | 数え方 |
   |---|---|
   | `f(...)`・`await f(...)`・`self.f(...)`・`obj.f(...)`。`create_task(f(x))`・`gather(f(x))` の中の `f(x)` | 呼ばれる関数が 1 段 |
   | `Cls(...)`（構築） | `Cls.__init__` が 1 段。構築で走る木の中のコード（dataclass の `__post_init__`・`field(default_factory=f)` の `f`・pydantic の検証子）も 1 段【仮 O48 (6) N1】 |
   | `Thread(target=f)`・`Process(target=f)`・`asyncio.to_thread(f, …)`・`run_in_executor(…, f, …)`・`Executor.submit(f, …)`・`functools.partial(f, …)` | `f` が 1 段（手引き 18.2 の 2。O48 (2) は手引きに列挙するかだけ） |
   | `Executor.map(f, …)`・`loop.call_soon(f, …)`・`add_done_callback(f)` | `f` が 1 段【仮 O48 (6) N2】 |
   | 起動時から常駐する worker（ツールは queue に積むだけ） | worker の関数を、積む行のある関数から 1 段【仮 O48 (6) N2】 |
   | `@property`・`cached_property` の属性の読み、`with X:` の `__enter__`/`__exit__`、`obj(...)` の `__call__` | 書かれた位置（属性の読み・`with`・`obj(...)` を書いた関数）から 1 段【仮 O48 (6) N1】 |
   | 引数の既定値の関数（`def g(q, writer=_write)` の中の `writer(q)`。呼ぶ側が別の値を渡していないとき） | 既定値の関数に降り、`writer(q)` を書いた関数から 1 段【仮 O48 (6) N9】 |
   | 呼び戻し（かっこを付けずに渡した関数名。`ExtClient(token_saver=_save)`）・`Depends(f)` | 呼ばれるか・いつ呼ばれるかは、木の外のライブラリの公式の文書で決め、決まらなければ決められない（手引き 19 の「動的な呼び出し」、D86 の 7）。深さは、関数の中で渡したなら渡した行のある関数と同じ、モジュールの一番上で渡したなら 0（`Depends(f)` はツールの引数で渡すので 0）【仮 O48 (1)・(7)】。かっこの無い名前は `grep -rnw '名前'` で探す |
   | デコレータの wrapper・middleware | 深さに数えない（中は読む。2 の 1） |
   | 同じ関数にいくつもの道で届く | いちばん浅い深さ。後で浅い道を見つけたら、その先を深さ 4 まで読み直す【仮 O48 (4)】 |
   | 起動した木の中のスクリプト（子プロセス）の中 | 【規則なし】（N4）。深さ 4 の内か外かで答えが変わるときだけ、決められない |

5. **木の中か外か**: 名前で木の中を検索する（`def 名前`・`class 名前`）。木の中に定義があれば木の中。同梱したほかのプロジェクトの
   コード（`vendor/`・`third_party/`）も木の中。テスト・例のファイルの関数も、ツールの道筋から呼ばれていれば木の中【仮 O48 (4)】。
   「定義へ移動」で飛べないことは木の外の印ではない（依存を入れていないため）。手元に無いファイル（sparse checkout の外。
   `*.yaml`・`logging.conf` など）も木の中として扱い、`git -C corpus/<tree> ls-tree -r --name-only HEAD` で探して
   `git -C corpus/<tree> show HEAD:<パス>` で読む【仮 O48 (4)】。
6. **受け手の型を確かめる**（手引き 12.2）: `self.client.fetch()` なら、`self.client` に入るもの（クラスの中の `self.client =` を全部）を
   見てから降りる。import の行で、どの定義かを決める（`as` の別名・相対 import・`__init__.py` の再輸出・`from x import *`）。組み込みの
   `set.add`・`dict.get`・`list.append` を、木の中の同じ名前のメソッドと取り違えない。型を確かめるために深さ 4 より奥を覗くのは
   よいが、そこで見つけた動作は深さ 4 の外。
7. **呼ばれうる先が複数あるとき**（`OPS[op]()` の表・設定で選ぶ実装・受け手のクラスが 1 つに決まらない・`getattr`）: 候補が読めれば
   全部を読む範囲に入れ、表や分岐に書かれた順に読む【仮 O48 (8)】。モデルが選べる鍵なら取りうる値の全体で考え、運用者が設定で
   選ぶなら「その設定で起動すれば届く」（3 の 1）。決められないのは、候補が木の外で増える形（entry_points のプラグインなど）か、
   選ばれ方が読み切れないときだけ。決められないとする前に、「あと 1 ファイル読めば決まらないか」を確かめる。
8. **`try: import X … except ImportError:`** は両方の枝を読む（どちらが走るかは任意の依存しだいで、どちらも届く。手引き 14.3）。
   `if TYPE_CHECKING:` の中の import は実行時に関係しない。
9. **木の外のライブラリの中は読まない**（手引き 18.2 の 2、19）。ライブラリの関数は、その呼び出し自体が環境を変えるかだけを見る
   （4・5 節）。ライブラリの中の書き込み（`from_pretrained` が重みをキャッシュに保存する、`sentry_sdk.init` の後に例外のたびに
   ライブラリが送る、など）は数えない【仮 O48 (3)】。数えないので、違反の割合は下限になる。ライブラリのソースは開かない
   （公式の文書を開くのは「中を読む」ことではない）【仮 O48 (3)】。
10. 長い関数では、ツールの道筋に届く分岐だけを読んでよい。届くか迷う分岐は読む。

## 3. 届くか

1. **届く**: ツールが呼ばれたとき、その行が実行される道が 1 つでもある（毎回でなくてよい。手引き 14.1）。次はどれも届く
   （手引き 14.3。条件の種類は記録しない）。
   - モデルが渡す引数の値による（`if save:`）。引数の既定値で起きる。
   - 初回だけ・無いときだけ変わる（`makedirs(exist_ok=True)`・`CREATE TABLE IF NOT EXISTS`・`unlink(missing_ok=True)`）。
   - 失敗・再試行・期限切れの道（エラー時の後始末、トークンの更新）。
   - 外部の状態（ファイルが無いとき、相手のサーバの応答しだい）。
   - 運用者の設定（環境変数・設定ファイル・起動の引数・目印のファイル・OS・任意の依存・運用者が書き換える前提の `config.py` の定数）。
     既定では起きて、設定で止められるもの（`if not NO_CACHE:`）も届く。
   - 起動の方法（3 の 4）。
   - ツールが積んだもの・始めたもの（queue・スレッド・プロセス）が、**呼び出しが返った後に**書く（手引き 14.1）。
   - 同じ呼び出しの中で作って消す一時ファイル（手引き 14.5）。

   条件が何で決まるか読み切れなければ、決められない。
2. **届かない**（手引き 14.2）:
   - 呼び出し先の取り違え（受け手の型で確かめる。2 の 6）。
   - 死んだコード: ツールの道筋から呼ばれていない（CLI・テスト・スクリプトからだけ呼ばれる）。**呼び出し元を木の中で全部検索して
     確かめる**（かっこの無い名前でも検索する）。
   - 定数で閉じた枝: `if False:`、どこでも書き換えない定数（`DEBUG = False`）の枝。ただし運用者が書き換える前提の `config.py` の定数は
     閉じていない（届く。D76）。「書き換える前提」かを見分けられず、それで答えが変わるなら【規則なし】（N5）。
   - 効果の前に必ず `return`・`raise` する。
   - モジュールの読み込み時に走る文（関数の外の文、モジュール水準の変数の初期化）。
3. **関数の中の import（遅延 import）**: 読み込まれるモジュールの一番上の文は、最初の呼び出しで走りうる。同じモジュールがサーバの
   起動時にほかで import されていれば、読み込み時なので届かない。されていなければ【規則なし】（手引きの封の前の仕分けで「まれ」
   として決めなかった穴 H-3-20）。
4. **一度だけの初期化**（`if _x is None: _init()`・`global _initialized`・`@lru_cache` の中に効果があるとき）: その初期化が、ツールの
   受付より前に必ず済んでいるかで決める。起動の方法はコードだけから決める（手引き 14.4）。

   | 初期化を先に済ませる場所 | 届くか |
   |---|---|
   | `main()` の中だけ、または `if __name__ == "__main__":` の中だけ | **届く**（`fastmcp run file.py:mcp` などで `main()` を通らずに起動できる） |
   | lifespan の中（`FastMCP(..., lifespan=…)` に渡した関数）で、必ず済ませる | 届かない |
   | モジュールの読み込み時（一番上の文、モジュール水準の変数の初期化） | 届かない |
   | `mcp` を包む部品の起動フック（`build(mcp, on_startup=init)` など） | **届く**（D86） |
   | どこでも先に済ませない | **届く**（最初の呼び出しで走る） |
   | どこで済ませるか読み切れない | 決められない |

   - lifespan が**条件つき**（`if os.environ.get(...):` の中で初期化する）なら、条件が偽のとき届く。**失敗を握りつぶす**
     （`try: … except: pass` の後に受付を始める）なら、失敗したとき届く（手引き 14.4）。lifespan の `yield` の後は終了時の処理で、
     先に済ませる初期化に数えない。
   - lifespan は `FastMCP(`・`Server(` の `lifespan=` を探す（uvicorn の `lifespan="on"`・FastAPI の lifespan にも当たるので、渡す相手を
     確かめる）。`mount` したサーバは、そのサーバと取り付け先の親の lifespan を読む。
   - 初期化の後に `None` に戻す行（`_x = None`）がツールの受付の途中で走りうるなら、再び届く。`atexit` の関数やテストの中で戻すのは
     数えない（D76）。
   - ツールの道筋が初期化を呼ばない（守りの `if` が無い）なら、その効果は道筋に無い。
   - **手引き 14.4 の表に無い起動の形**（サーバを関数の中で作る（H-3-17）、ツールの登録が `main()` の中だけ（教科書の境目 6）、一番上の
     初期化が `mcp.run()` の後ろにある・条件つき・失敗を握りつぶす（H-3-19））で答えが決まるときは【規則なし】。
5. **値の出どころ**: 「モデルが決める値か」を決める前に、値の出どころを全部たどる（`global` での再束縛、同じ関数での `os.environ` の
   書き込みと読み戻し、書式テンプレートの穴）。同じツールの中で引数から届けば、モデルの値。別のツールが入れてメモリに残った値が、
   判定しているツールのコマンドや書き先を決める形（ツールをまたぐ値の流れ）は【規則なし】（N6）。
6. `atexit` に登録した関数が、ツールの溜めたものを終了時に書く形は【規則なし】（N2）。

## 4. 環境を変える動作（sink）

**問い**（手引き 15.1）: その動作は、呼び出しの後に残る何か（**ホストのファイル・DB・相手のサーバの状態・残る設定**）を変えるか。
届いて変えれば `違反`。下の表の行と問いの文が違う答えを指すときは、表の行を採る（手引き 15 の前書き）。表に行が無いものは、
問いの文で決める【仮 O48 (4)】。

| 種類 | 変える（違反） | 変えない |
|---|---|---|
| ファイル | 書く・足す・作る・消す・移す・権限を変える。ログ・キャッシュ・一時ファイル（同じ呼び出しの中で作って消すものも）・ディレクトリの作成（`mkdir(exist_ok=True)` は無いとき）・`touch()`・`'a'` で開くだけ（無ければ作る。`flock` のためでも）・`print(..., file=開いたファイル)`。開くモードは `mode=` まで確かめ、変数ならさかのぼり、条件で変わるなら両方の枝を考える: `'w'`・`'a'`・`'x'`・`'w+'`・`'a+'`、書く `'r+'` | 読み取り（`'r'`・`'rb'`。atime などの変化も）、`io.StringIO` |
| DB | データ・スキーマの変更（`INSERT`・`UPDATE`・`DELETE`・`CREATE`・`DROP`・`ALTER`・`REPLACE`）、残る設定・保守（`PRAGMA journal_mode=WAL`・`VACUUM`）、ORM の `add`・`delete`・`save`・`merge`（どの SQL になるかは公式の文書で）、呼び出しの中の `create_all`、グラフ DB の `CREATE`・`MERGE`・`SET`・`DELETE`、キーと値の DB・検索エンジンへの書き込み、**無いファイルを作る `sqlite3.connect`**（ほかの「開くと作る」形（`shelve`・`dbm` の `'c'`）は、作ることを公式の文書で確かめられれば同じ【仮 O48 (3)】） | `SELECT`、接続単位の設定（`PRAGMA foreign_keys=ON`）、トランザクションの制御（`BEGIN`・`COMMIT`）だけ、`.commit()` だけ（何を確定するかを見る） |
| 相手のサーバ（HTTP） | `PUT`・`PATCH`・`DELETE`。`POST` は**相手の API の意味**で決め、作成・更新・削除なら違反（5 節。認証・トークン・ログインの `POST` も同じで、文書に無ければ決められない）。メソッドを引数で受けるヘルパーは呼ぶ側の値までさかのぼり、モデルがメソッドを決められるなら違反。GraphQL は送る文が `mutation` なら違反（`POST` の意味）。文をモデルが決めるなら違反【仮 O48 (4)】 | `GET`・`HEAD`・`OPTIONS`（`GET` で送信・作成する API でも、表の行を採って変えない）、照会の `POST`（検索 API・RPC の読み取り）、GraphQL の `query` |

| プロセス・コード | `eval`・`exec`。プロセスの起動（`subprocess`・`os.system`・`os.popen`・`asyncio.create_subprocess_*`・`pexpect`）は下の「プロセスの起動」で決める | スレッドの起動だけ |
| ログ（ロガーへの出力） | **このサーバの起動で走るログの設定がファイルに書く**とき（下の「ログ」） | 標準出力・標準エラー（`print`、ログの設定が無いとき、`basicConfig(level=…)` だけのとき） |
| 状態の保存 | トークン・セッションのファイルへの保存、ディスクのキャッシュ（`diskcache`・`requests_cache`・`joblib.Memory`・`shelve`） | — |
| 数えないもの | — | **プロセスのメモリの中の状態**（モジュール水準の辞書・`lru_cache`・クラスの属性。D76 の 2。数えるかは【未決 O47】）。`os.environ` の書き換え・`os.chdir`・ログの設定の書き換え【仮 O48 (4)】。クライアントへの通知（`ctx.info()`・`ctx.report_progress()`） |

**プロセスの起動**（手引き 15.1、D76・D86）:
- 起動するコマンドをモデルが決められる → 違反。
- コマンドが定数 → そのコマンドが実際に何をするかを公式の文書で調べる（名前から「読み取り」と決めない。例: `git status` は既定で
  index を書き出すと文書にある）。環境を変えるなら違反、変えないなら違反でない、分からなければ決められない。
- コマンドを運用者が設定で決める → 既定値・設定の見本・文書で分かれば、そのコマンドで同じように決める。分からなければ決められない。
- 定数のコマンドに、モデルが引数・オプションを渡せる（`git diff <path>`）→ モデルが書けるオプションに環境を変えるもの（`--output=`）
  があれば違反（`shlex.quote` は `-` で始まるオプションを通す）。
- 子プロセスの標準入力への書き込みは、それ自体は変えない。子プロセスの動作を全部数える。木の中のスクリプトなら読む（深さは 2 の 4 の
  表の最後の行）。木に無いプログラムは、名前から推さずに決められないとする。
- 起動して残る子プロセス（常駐するサーバ）も、ここで決める。

**ログ**（手引き 15.1・18.3）:
- ツールの道筋に `logger.xxx(...)` があれば、ロガーの出どころを import でさかのぼる。名前の付いたロガーの記録は、ルートのロガーにも
  伝わる。`basicConfig` は最初の 1 回だけ効く。
- 出力先の設定は、**木全体**を正規表現 `FileHandler|basicConfig|logger\.add|dictConfig|fileConfig|addHandler` で検索し、当たりのうち
  **このサーバの起動で走るもの**を選ぶ（起動の入口 `if __name__ == "__main__":`・`main()`・`pyproject.toml` の `[project.scripts]` から
  その行に着くか。ほかのサーバ・テスト・例のファイルの設定は外す）。手元に無い設定のファイル（`logging.conf`・`*.yaml`・`*.ini`）と
  起動の定義（`*.service`・`Procfile`・`Dockerfile`・起動のスクリプトの `--log-config` など）も `git ls-tree` で探して読む。
  `dictConfig` は handler の `class` と `filename` を読む。
- ファイルへの設定が `main()` の中だけにあっても届く（運用者の起動のしかたで走る）。設定が 1 つも無ければ Python の既定（警告以上を
  標準エラーへ）で、ファイルには書かない。
- ログの水準で書かれない記録（水準が `WARNING` 固定で `logger.info` だけ、水準を環境変数で変えられる）は【規則なし】（N3）。
- **いつ確かめるか**: `違反でない`・`不明`・`違反（深さ 4 の外）` にするときは、道筋にロガーへの出力が無くても毎回（D87 の 3）。
  違反で止めるときは、読む順でその違反より前にロガーへの出力があるときだけ（D88）。

**そのほか**:
- `:memory:` の DB の変更、同じ呼び出しで `ROLLBACK` する変更は【規則なし】（「まれ」として決めなかった穴 H-4-3）。
- 判定するのはコードの動作で、docstring・コメント・ツールの説明文・木の中の関数の名前（`get_`・`list_`）は根拠にしない
  （手引き 11.2。どこを読むかの手がかりにはしてよい）【仮 O48 (4)】。中を読めない木の外の関数を名前で決める扱いは 5 節。

## 5. 木の外の関数・相手の API の意味の決め方【仮 O48 (3)】

木の外の関数（SDK の `client.sync()` など）が環境を変えるか、`POST` が作成・更新・削除か照会かは、次の順で決める。

1. 名前が作成・更新・削除・書き出し・送信（`create_`・`update_`・`delete_`・`write`・`save`・`send`・`put_`・`post_` など）か、
   読み取り（`get_`・`list_`・`search`・`read`・`fetch` など）を**はっきり示す**なら、名前で決める。`evidence` に「API 名から」と
   添える（名前で決めた件を後で数えるため）。
   - 手引きが名前で決めてよいとするのは `POST` の API 名だけ（15.1、D86 の 15）。木の外の関数に広げるのは O48 (3) の推奨 (a) で、
     学生が封の前に選ばなければ消える（そのときは 2 から始める）。
2. 名前で決まらなければ、そのライブラリか相手の API の**公式の文書**を開いて決める。決めた文書の URL を `evidence` に添える。
   ツールの docstring は相手の API の文書ではない。
   - AI に聞いてよい（プロンプト 1。8 節）。ただし AI の答えだけでは決めない。AI が挙げた公式の文書を自分で開き、文書が答えを支えて
     いるときだけ採る。
3. それでも決まらず、それで答えが変わるなら、その動作は決められない（6 節）。
4. SDK のメソッドが HTTP を隠していて、メソッドが見えないとき（`api_call("users.info")` など）も、相手の API の意味を 1〜3 で決める。
5. 「確かめた」と言えるのは、公式の文書を自分で開けたときだけ（手引き 19）。手元で動かして確かめたものは、確かめたことにしない。
   ライブラリのソースは開かない（2 の 9）。

## 6. 答え（`outcome`）と `不明`

1. 次の順に当て、最初に当てはまったものを答えにする（D82、手引き 18.2・18.3 の当てはめ）。

   | 順 | 当てはまるか | `outcome` |
   |---|---|---|
   | 1 | 1 の 2 で対象外 | `対象外` |
   | 2 | 深さ 4 の中に、届いて環境を変える動作が 1 つでもある | `違反` |
   | 3 | 深さ 4 の中に無く、深さ 4 より奥で**偶然**見つけた、届いて環境を変える動作がある（探しに行かない） | `違反（深さ 4 の外）` |
   | 4 | 深さ 4 の中に、違反になりうるのに決められない動作がある | `不明` |
   | 5 | 上のどれでもない | `違反でない` |

   - 深さ 4 の中の決められない動作と、奥の違反が重なるときは `違反（深さ 4 の外）`（順 3 が先。手引き 18.3 の字義）。
2. **決められない**とは: 調べても、届くか、または環境を変えるかが決まらないこと。典型（手引き 19）: 書き先・宛先・コマンドが木の外の
   戻り値や実行時の外部の状態で決まる／相手の API の意味が文書にもコードにも無い／起動の方法・初期化の場所が読み切れない／動的な
   呼び出し（`getattr`・プラグイン・木の外が木の中の関数を呼び戻す）で、呼び出し先や呼ばれる時点が決まらない。
   - 調べれば分かるもの（開いていないファイルや文書がある）は、決められないにしない。目安は 1 件を読み始めて 20〜30 分。30 分の
     時点で、次に開くもの（ファイル・文書）を名指しできれば続け、できなければ決められないとする【仮 O48 (4)】。
   - **届くかを決められなくても、届いたとしても環境を変えない動作**（`GET`・通知・読み取り）は、`不明` の理由にしない（D86 の 10）。
3. 【規則なし】の点で、それで答えが変わるなら、その点は決められない（手引き 22。20〜30 分を待たなくてよい）。答えが変わらなければ、
   読み方を決めて進む。判定の途中で規則を足さない。
4. 決められない点があっても**読むのはやめない**。後ろに違反があれば、答えは `違反`。
5. **最初の違反で止める**（D88）: ある動作が届いて環境を変えると決まり、読む順でそれより前の候補が全部決まった（決められないと決めた
   ものも決まったとみなす）ら、そこで読むのをやめる。読む順は、浅い深さから、同じ深さでは呼ばれる行の順【仮 O48 (4)】（呼ばれうる先が
   複数なら 2 の 7）。`違反（深さ 4 の外）`・`違反でない`・`不明` になる件は、深さ 4 まで全部読む。
6. 深さ 4 までが大きく、目安の時間で読み切れないときも読み続ける。それでも読み切れずにやめるなら `不明`【仮 O48 (4)】。

## 7. 記録（`outcome` と `evidence` だけ）

表は名簿の 9 欄（変えない）＋ `outcome` ＋ `evidence`（D90）。考えたこと・時間・ラベル・メモは書かない。

| `outcome` | `evidence`（D91・D92） |
|---|---|
| `違反`・`違反（深さ 4 の外）` | **反する行までの道筋 1 本** |
| `不明` | **決められなかった点までの道筋 1 本**（複数あれば読む順で最初のもの）。何が決められないかを `: …` で添えてよい |
| `対象外` | 理由を 1 文（宣言の行と、なぜ登録されるツールの宣言でないか） |
| `違反でない` | 空 |

- **道筋の形**: 本体は書かず、本体が呼んだ先から書く。木の中の関数は定義の行で `ファイル:行 名前`、木の外の関数は `名前（外）`。
  ` → ` でつなぎ、最後に `→ ファイル:行: 何をするか`。本体の中の行そのものなら `ファイル:行: 何をするか` だけ、木の外の関数そのものが
  反するなら `名前（外）: 何をするか`。
  - 判定した関数が名簿の `tool` と違うとき（1 の 1）と、反する行が wrapper・middleware の中にあるとき（2 の 1）は、最初にその関数の
    `ファイル:行 名前` を書く。
  - 決められなかったのが呼び出しでない（登録の枠組み・読み切れなかった所など）ときは、関わる行を `ファイル:行: 何が決められないか`
    と書く。
  - 同じ関数の中で DB への接続（無いファイルを作る）と、その DB を変える文が続くときは、1 つの動作として道筋を DB を変える文まで書く
    【仮 O48 (8)】。
  - 例: `notes_server.py:34 _search → notes_server.py:29 _remember_query → notes_server.py:30: open(..., "a") に追記`
  - 例: `client.py:20 Client.sync → httpx.Client.post（外）: POST /items/sync の意味が文書に無い`
  - 例: `client.create_order（外）: 注文を作る／API 名から`
- パスは木の根から書く（`corpus/<tree>/` を付けない）。つなぎは ` → `（`->` にしない）。1 つのセルに改行を入れない。
- 添えてよいのは、公式の文書で決めたときの URL と、名前で決めたときの「API 名から」だけ（最後に全角の「／」で区切る）。
- 行は自分で開き直して書く（AI の答え・FAQ の行番号を写さない）。
- 書いたら確かめの道具にかける: `.venv/bin/python scripts/check_survey_practice.py <表> --sheet <配った表>`（名簿の欄が配った表と同じか
  も見る。`--sheet` を省くと練習の表と照らす）。
- 翌日に見直して答えを変えたら、行を直すだけ（変えたことは書かない。D90）。

## 8. AI の使い方（D95）

AI は判定の材料を集めるのに使ってよい。記録する答えは人が決める。プロンプトの文面は `survey/prompts/` に固定し、変えない
（`{…}` の穴を埋めるだけ）。

| プロンプト | いつ | 渡すもの | 答えの扱い |
|---|---|---|---|
| 1 木の外の関数（`1_library.txt`） | 5 節の 2 で、木の外の関数・API の意味が分からないとき | パッケージ名と版、関数の名前、呼び出しの 1 行 | 答えに付いた公式の文書を自分で開いて確かめたときだけ採る |
| 2 コード解説（`2_explain.txt`。続けて聞くときは `2_followup.txt`） | 分からないコードに出会ったとき。分からない部分を続けて聞いてよい | 分からない部分のコード（行番号つき）、そのファイルのパスと import の行 | 手がかりにだけ使う。挙げられた行を自分で開いて確かめ、判定は自分でする |
| 3 件の答え（`3_case.txt`。足りないファイルを求められたら `3_followup.txt`） | **人が `outcome` と `evidence` を書いた後**（参考） | 判定に要るファイルを全部: 本体のファイル、たどった木の中の関数のファイル、wrapper・middleware・登録とサーバを作る行のファイル、ログの設定のファイル。AI が求めた木の中のファイルは渡す | 人の答えと違えば、AI が挙げた行を自分で開いて確かめる。答えを変えてよい（D95）。プロンプト 3 の前と後のどちらの答えを主の数にするかは【未決】（10 の 3） |

- **伏せる**（貼る前に。宣言とその言い換えを AI に見せない）: 宣言の全体（`annotations=` から閉じかっこまで。複数行でも。
  `ToolAnnotations(…)`・辞書 `{"readOnlyHint": …}`・宣言を入れた変数の定義 `RO = …`・`read_only_hint=`・`readOnlyHint` を含む行）、宣言を
  述べる docstring・コメント・ツールの説明文（「read-only」「does not modify」など）、秘密の値（API キー・トークン）。伏せた所は
  `[REDACTED]` に置き換える。
- **聞かない**: 「読み取り専用か」「宣言に反するか」「正しいか」と、その言い換え（「これは環境を変える？」）。プロンプト 3 の決まった
  文面だけは、規則に照らした答えを聞く。宣言の値・解析器の出力・自分の結論は渡さない（手引き 21 の 6）。
- **会話の単位**: プロンプト 1・2 は件ごとに新しい会話（同じ件の中の続けての質問は同じ会話）。プロンプト 3 は、その件のための新しい
  会話（足りないファイルを渡すのは同じ会話）。前の件の判定を AI に伝えない。
- **使う AI**: この repo の文脈を持たないもの（この repo を開いた Claude Code、この repo の文書を読み込ませた会話・Project は使わない）。
  記憶（メモリ）を切る。エディタに組み込まれた AI の機能は切る。モデルの名前と版は【未決】（10 の 3）。所属大学の生成 AI の規程を、
  判定の始めと終わりに確かめる（事前登録の下書き (e) の AI の 6）。
- **ログ**（AI の記録はこれだけ。表の欄は増やさない）: 1 件 1 ファイル（判定表と同じ所の `ai_logs/<pair_id>.md`）。先頭に件の id・
  日時・使った AI（名前・版・画面・記憶なし）と、プロンプト 3 を使う件では**プロンプト 3 の前の `outcome` と `evidence`**。続けて、使った
  プロンプトの番号ごとに、渡した入力と答えの全文、自分で確かめたか（開いた URL・行）を書く。消さない。
- 英語の文書の機械翻訳は使ってよい（AI の利用に数えない。訳すのは自然言語の文書だけで、コードと宣言は貼らない。D86 の 14）。

## 9. 道具と進め方

- 使う: 文字の検索（VS Code の検索・`grep`・`git ls-tree`・`git show`）、エディタの移動（定義へ移動・参照を探す）、AI（8 節のとおり）
  （D93）。
- 使わない: 呼び出しの一覧や書き込みの候補を自動で出す道具（pyan3 などの呼び出しグラフの道具・CodeQL・Semgrep・Bandit・AuthGap）。
  正解（人の判定）を道具に寄せないため（D93）。
- 木の中のコードは実行しない。手元で動かして確かめたことは、確かめたことにしない（手引き 19）。
- 実態調査を全部判定し終えるまで、AuthGap と比べる相手の道具の出力（矛・不・summary）と、それをもとにした過去の判定（v4 の判定
  `evidence/population_v4/v4_judgments.json` など）を見ない（D82）。
- 判定の途中で集計を見ない（結果の欄を数える・並べ替える・絞り込む。手引き 21 の 2）。
- 判定は抜き取った列の順に行う。途中の結果を見て、件数・順・規則を変えない（規則に無い形は 6 の 3）。
