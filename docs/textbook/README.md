## この文書の目的

### 一言で言うと

この教科書は、**学生が AuthGap というシステムとこの研究を最初から最後まで理解し、そのうえで最終評価の手動判定を、迷わず、理由を自分で説明しながら行えるようになるため**の本です。判定のときに従う規則そのもの（正本）は、この本ではなく、封をした事前登録 §2.12 と判定の手引きです。この本は、その規則を「なぜそう決めたのか」「実物ではどう見えるのか」まで説明します。

### たとえ話 — 運転免許の教本と道路交通法

自動車教習所で使う教本を思い浮かべてください。教本は、道路交通法をやさしく言い換え、図と例を付け、「なぜこの規則があるのか」を説明します。教本を読み、教習所の中で練習してから、初めて公道に出ます。

けれども、教本と法律が食い違ったら、従うのは法律です。教本は「分かるための本」で、法律は「従う決まり」です。

この研究では、次のように対応します。

| たとえ話 | この研究 |
|---|---|
| 道路交通法 | 封をした事前登録 §2.12（`docs/preregistration.md`）と判定の手引き（`docs/final_judging_guide.md`）。今はどちらも下書き（`docs/drafts/prereg_2_12_draft.md`、`docs/drafts/final_judging_guide_draft.md`） |
| 法律ができた理由の記録 | 決定の記録 `docs/decisions.md`（D1〜D71） |
| 教習所の地図 | 最終評価の手順書 `docs/final_evaluation_procedure.md`（自分で「地図であって規則ではない」と書いている） |
| 教本 | この教科書 |
| 教習所の中での練習 | 第 53・54 章の実地演習と、手順書 6.8 節の判定の練習（v4 のデータ） |
| 公道 | 最終評価のデータの判定（段階 7） |

表の読み方: 左の列がたとえ話、右の列がこの研究での実物です。たとえば 2 行目は「法律がなぜそう決まったかを知りたければ、決定の記録 `docs/decisions.md` を開く」と読みます。

### 小さな例 — 1 件の判定で、この本のどこを使うか

最終評価では、たとえば次のような 1 行を判定します（判定の手引きの下書き 20.1 節の練習用のサーバの組。[第 53 章](ch53.md)で一通り練習します）。

| 欄 | 値 |
|---|---|
| `tree`（木） | 練習用のサーバ（`demo`） |
| `unit`（ツール） | `search_notes`（宣言 `readOnlyHint=True`） |
| `site`・`kind` | `builtins.open`・`FS_WRITE` |
| `decl`（照らす宣言） | `D1` |
| `reasons`（解析器の理由） | `fs_write` |
| `locations`（効果の位置） | `server.py:12` |

この 1 行を判定するのに、この本の次の章を使います。

1. 欄の名前が何を指すか（木・ユニット・site・kind・宣言・理由コード）→ 第 11〜18 章と[付録 A](appendix-a.md)。
2. 解析器がこの組をどう見つけたか（入口 → 呼び出しをたどる → 効果 → 宣言と照合）→ 第 12〜17 章、実物の manifest は[第 19 章](ch19.md)。
3. 原ソースの `open(..., "w")` が書き込みかどうか、`_lookup` から `_save_cache` へどう届くか → [第 9 章](ch09.md)（Python の読み方）。
4. 2 つの問い（到達するか・宣言に反するか）と手順 A〜H → 第 48〜50 章。
5. 「正」にした後に付ける書き込み先の種類（この例では、読み返しが無いので「その他・不明」）→ [第 51 章](ch51.md)。
6. 迷ったとき・決められないとき → [第 52 章](ch52.md)（不明の目安は 20〜30 分）。
7. 判定を終えた後、数字にまとめて論文に書く → 第 38・39・55 章。

### 一歩ずつ — この本が目指す 3 つの「できる」

この本を読み終えたとき、次の 3 つができることを目指しています。

1. **研究を自分の言葉で説明できる。** 何を測る研究か（宣言 D と実効 M の照合。[第 6 章](ch06.md)）、なぜ静的解析なのか（[第 7 章](ch07.md)）、なぜ「不明」を数えるのか（研究の芯。[第 6 章](ch06.md) 6.4 節）を、原典を見ずに説明できる。
2. **システムの出力を読める。** manifest の欄、行の注記（`contradiction:D1` など）、`summary.json`、`contradictions.json` を開いて、解析器が何を見て何と答えたかを言える（第 18・19 章）。
3. **最終評価の判定を、規則どおりに、根拠つきで行える。** 1 件ごとに「到達するか」「宣言に反するか」に答え、正・誤・不明を付け、根拠のファイルと行を第三者がたどれる形で書ける（第 48〜54 章）。

### なぜそうするのか — 判定する人が、研究の全体を知っている必要がある

最終評価の判定は、学生 1 人が行い、AI（LLM）は使いません（D67 の 4、D70 の 3）。2 人目の判定者は保留です（D70 の 8）。つまり、判定の質を支えるのは、判定する人の理解と、残した根拠だけです。

判定の手引きは、規則を短く書いた文書です。規則の文面だけを覚えて判定すると、手引きに書かれていない形に出会ったとき、規則の「意図」から外れた判断をしてしまいます。たとえば「ログを 1 行書くだけで読み取り専用に反するのは厳しすぎる」と感じて、黙って「誤」にしてしまう、といった判断です（実際は、採った原理を字義どおりに当てるので「正」で、軽さは書き込み先のラベルで表します。第 43・48 章）。規則がなぜそうなっているかを知っていれば、こうした取り違えを防げます。

もう 1 つの理由は、論文です。判定の手続きと限界を論文に書くのは学生です。「なぜ木を単位にするのか」「なぜ重みを付けないのか」「なぜ AI を使わないのか」と査読で問われたとき、答えられる必要があります（[第 56 章](ch56.md)によくある疑問を集めました）。

### よくある誤解

- **「教科書に書いてあるから、それが判定の規則だ」**: 違います。正本は封をした事前登録と判定の手引きです。この本と手引きが食い違ったら、手引きに従い、食い違いを判定表の `note` 欄に書いてください（[第 0 章](ch00.md)）。
- **「v4 の判定の例が正解だ」**: 違います。v4 の判定は本記録者（AI）が行ったもので、正解ではなく考え方の例です（手引きの下書き 20.2 節）。練習で食い違ったら、手引きの穴として扱います（[第 54 章](ch54.md) 54.17 節）。
- **「全部を読んでからでないと判定の章に進めない」**: 順に読むのが基本ですが、目的別の近道も用意しました（下の「読み方」）。ただし、[第 0 章](ch00.md)だけは必ず最初に読んでください。誰が何をしたか、どの文書が正本か、決まっていないものの書き方が書いてあります。
- **「この本の数字はそのまま論文に使える」**: 使えません。この本に出てくる v2・v3・v4 の数字は、開発用のデータや本記録者の判定から出たものです。論文の数字は、最終評価で学生が出します（D60・D66 の 5）。

### 手作業ではどう使うか

最終評価の作業の中で、この本は次の 3 つの場面で使います。

1. **データを見る前（段階 0〜2）**: 第 45〜47 章で段階の全体を確かめ、[第 46 章](ch46.md) 46.16 節の未決 9 項目を封の前に片付けます。第 53・54 章で練習し、1 件の判定にかかる分数を測ります。
2. **判定の最中（段階 7）**: [付録 E](appendix-e.md)（判定の早見表）と[付録 F](appendix-f.md)（判定の言葉の対照表）を横に開いておき、迷ったら第 48〜52 章の該当の節に戻ります。言葉を忘れたら[付録 A](appendix-a.md) を引きます。
3. **判定の後（段階 8・9）**: 第 38・39・55 章で数字の出し方と書き方を確かめます。

### この節のまとめ

- この本の目的は、システムと研究を理解し、最終評価の手動判定を理由つきで行えるようになること。
- 判定で従う正本は、封をした事前登録 §2.12 と判定の手引き。この本はそれを説明する教本。
- 判定は学生 1 人で、AI は使わない。だから、判定する人の理解と、残す根拠が質を支える。

## この文書の読み方

### 一言で言うと

**頭から順に読む**のが基本です。各章は同じ型で書いてあり、専門語は初めて出た所で「やさしい言い換え・正確な定義・例」の 3 点で説明します。出典（ファイル名と行番号）は段落の末尾の「（出典: …）」にまとめてあるので、本文を読むときは飛ばし、確かめたいときに開いてください。

### たとえ話 — 料理の本の読み方

料理の本は、最初の数ページに「計量カップの大きさ」「火加減の言い方」「材料の切り方」を書き、その後にレシピが続きます。レシピは毎回同じ順（材料 → 下ごしらえ → 手順 → コツ）で書かれているので、2 つ目のレシピからは迷わず読めます。この本も同じで、[第 0 章](ch00.md)が「計量カップ」、各章が同じ型の「レシピ」です。

### 小さな例 — 1 つの節の型

本文のどの節も、原則として次の順に並んでいます。

| 順 | 見出し | 何が書いてあるか |
|---|---|---|
| 1 | 一言で言うと | 節の結論を 1〜2 文で |
| 2 | たとえ話 | 身近なものに置き換えた説明 |
| 3 | 小さな例 | 短いコード・表・数字 |
| 4 | 一歩ずつ | 例の各行・各欄が何を意味するか |
| 5 | なぜそうするのか | 決めた理由と決定の番号（D○○） |
| 6 | よくある誤解・つまずき | 取り違えやすい点 |
| 7 | 手作業ではどう使うか | 最終評価の判定のどの場面で使うか |
| 8 | この節のまとめ | 2〜3 行 |

表の読み方: 上から順に読めば、結論 → 直感 → 具体 → 細部 → 理由 → 注意 → 実践 → 復習、と進みます。急いでいるときは 1 と 7 と 8 だけを読み、後で 3〜6 に戻る読み方もできます。

各章の最初には「**この章で分かること**」と「**この章の位置づけ**」（前後の章とのつながりと、手作業との関係）があります。章の最後には「**よくある誤解のまとめ**」「**この章のまとめ**」「**演習**」（手を動かす問題）「**確認問題**」があります。演習と確認問題の答えは、本文ではなく**[付録 D](appendix-d.md)** にまとめてあります。

### 一歩ずつ — 記号と表記の約束（詳しくは第 0 章）

### なぜそうするのか — 理解と確かめの両方を 1 冊で

この本は、2 つの読み方を両立させるために書いています。

- **理解のための読み方**: 本文を順に読み、たとえ話と例で直感をつかむ。
- **確かめるための読み方**: 本文の主張を、段落の末尾の出典から原典で確かめる。この研究の規則 1（未検証の統計を引用しない）と規則 6（仕様書と実データが食い違ったら実データを採り、仕様書の値も残す）を守るためです（`CLAUDE.md`）。

出典を段落の末尾にまとめたのは、学生の評価（「詳細度とわかりやすさが弱い」）を受けて、本文の流れを止めないためです。
