## 第 0 章 この教科書の読み方 — 表記・誰が何をしたか・読む順番 の答え

### 演習の答え

**演習 0-1**

1. 3754 行目には「5. v3 と並べてよいが、版もデータも違うので「改善」「悪化」とは書かない。論文には使わない。」と書いてあります。
2. 上へさかのぼると、3743 行目に見出し「## D66（2026-09-29）凍結版の中間検証（v4）— 本記録者が新しいデータで確かめる。**結果を見て解析器を変えない**」があります。3754 行目は、その「規則」の 5 番目の項目です。つまり **D66 の 5** です。
3. 3849〜3904 行目は **D70 の 3** です（見出しは 3836 行目の「## D70（2026-10-01）最終評価の段階 0 の残り」）。「判定は人が行う。AI（LLM）は、コードについての事実を調べる補助としてだけ使ってよい」という決定で、2026-10-02 に改訂されたものです。判定を決めて記録するのは学生で、AI には判定させません。あわせて、6 つの条件（AI が示した行は自分で開く、事実だけを聞き宣言の値と解析器の答えを渡さない、見落としは先に自分で読む、`ai_used` などを記録する、repo の文脈を持たない AI を使う、事前登録と論文で開示する）、引き続き使わないもの（不の組への LLM の対照腕、2 人目の判定者の代わり）、改訂の理由、誤りの向き、O45 への答えが書かれています。3895 行目からは、2026-10-01 の改訂前の文面（「最終評価の判定では LLM（AI）を使わない」）が引用で残っています。

考え方: 行番号だけを見ても、どの決定かは分かりません。見出し（`## D66` のような行）まで上にさかのぼって、初めて番号が分かります。判定の記録で決定を引くときも、行番号と決定の番号の両方を書くと、後で行がずれても探せます。

手がかり:

- 決定の番号は 4 より大きく（宣言は D1〜D4 の 4 つしかない）、「の 1」「の 3」のように項目の番号が付きやすい。

- 迷ったら、決定の D1〜D4（`docs/decisions.md:1231` の D1 など）の中身と照らして、文の意味が通るほうを採ります。

### 確認問題の答え

**確認問題 0-1**: v4 の判定をしたのは**本記録者**（この repo で解析器を作り、決定の推奨と記録を書いてきた AI、Claude）です。原ソースの確認は木ごとに agent（本記録者が仕事を分けて渡した別の AI の実行）に分け、誤・見落とし・不明の根拠を本記録者が見直しました。人は見直していません（`docs/population_v4.md:15-16,68`、`evidence/population_v4/v4_judgments.json:2`、`docs/final_evaluation_procedure.md:251-252`）。

論文に使わないのは、D66 の 5（`docs/decisions.md:3754`）で「論文には使わない」と決めたからです。その理由は 2 つあります。

1. v4 の判定は AI の判定で、独立した人の判定ではない。しかも解析器を作ったのも同じ本記録者で、作った本人の味見のような身内の評価になる。
2. v4 は本記録者が結果を見たデータなので、v2・v3 と同じく学生の最終評価のデータから除く約束になっている（D66 の 3、`docs/decisions.md:3752`）。

v4 の数字（たとえば D1 / D2 の矛の精度 76.7% = 46 / 60）は、凍結した解析器がどう振る舞うかの手がかりとしてだけ使います（[第 37 章](ch37.md)）。

**確認問題 0-2**: 第 3・4 章 → 第 9・10 章 → 第 13〜20 章 → 第 21・22 章 → [第 37 章](ch37.md) → [第 39 章](ch39.md) → [第 43 章](ch43.md) → 第 45〜52 章 → 第 53・54 章（演習）→ [第 55 章](ch55.md) → [付録 E](appendix-e.md)・F の順です。

理由の要点: 起動のしかたと宣言の意味（第 3・4 章）、原ソースを読む力（第 9・10 章）、解析器の出力を読む力（第 13〜20 章）がないと、判定の規則（第 45〜52 章）を当てられないからです。第 21・22 章は判定の作法の土台、[第 37 章](ch37.md)は v4 で出た誤りの類、[第 39 章](ch39.md)は判定の結果がどんな数字になるか、[第 43 章](ch43.md)は裏方の書き込みの考え方です。演習で練習してから集計（[第 55 章](ch55.md)）に進み、判定の最中は[付録 E](appendix-e.md)・F を引きます。

**確認問題 0-3**: [agent] は、agent が「原文を読んだ」と報告したもので、本記録者は照合していないものです。論文の根拠に使うには、**学生が自分で原文を開き、引用された文字列が本当に原文にあるかを照合して、[確認] に上げてから**使います。照合できなければ使わないか、「未検証」と明記します（`docs/incidental_writes_practice.md:12-15`、`CLAUDE.md` の規則 1）。

「保留」と「未決」の違い:

- **保留**は、決める時期（期限）を決めて、それまで待っているものです。例: 2 人目の判定者と判定の一貫性の確認（D70 の 8）。期限は「データを見る前、遅くとも段階 6 の抜き取りのコミットの前」で、それまでは D67 の 4（判定者は学生 1 人）が既定でした。この例は、期限より前の 2026-10-03 に D73 の 1 で決まりました。
- **未決**は、まだ誰も決めておらず、決める時期も決まっていないものです。例: 最終評価で CodeQL を見落とし探しの補助に使う案（D71 の「任意の案（未決）」、`docs/decisions.md:3953`）。やらないまま進んでもよく、やるならデータを見る前に事前登録に足すものでした。この例は、2026-10-03 に D72 の 1 で「使わない」と決まりました。

（2026-10-03 の D72・D73 で、例に挙げた 2 つが決まったので、答えに今の状態を書き足した）

**確認問題 0-4**: 矛盾しません。主語が違うからです。

- 「**解析器は LLM を使わない**」は、解析器を走らせたときの性質です。解析器は標準ライブラリの `ast` で決まった手順で動き、同じ入力から同じ結果を出します。
- 「**研究の遂行に AI を使った**」は、研究を進める作業の話です。解析器の実装、v4 の判定、手順書と手引きの下書き、決定の推奨、コミットの共著者などに AI（本記録者）が関わりました。

論文では、この 2 つを別々に書きます。前者は解析器の性質として方法の節に書き、後者は研究の遂行に AI を使ったこととして開示します（O45 の 4、`docs/open_questions.md:1270-1272`、`docs/llm_judgment_survey.md:165-168`）。さらに、最終評価の判定は学生 1 人が決めて記録し、AI はコードについての事実を調べる補助にだけ使ったこと、その範囲（`ai_used` が「あり」の件数）も書きます（D70 の 3、`docs/decisions.md:3885-3888`）。
