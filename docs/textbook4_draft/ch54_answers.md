#### 演習 54-3（自分で変種を作る）の答え

**変種のコード**（第 54 章 54.9 節のサーバ A の 18〜21 行を変えたもの。本書の作例）:

```python
18  @asynccontextmanager
19  async def lifespan(server):
20      try:
21          _ensure_index()
22      except OSError:
23          pass
24      yield {}
```

**答え**: **到達する**。組は**正**です（D1 に反する）。

| 欄 | 答え |
|---|---|
| `reachable` | はい |
| `condition_type` | `失敗・期限切れ` |
| `condition` | `起動時の lifespan の初期化（makedirs）が OSError で失敗したとき。受付は始まり、_index は None のままなので、最初のツール呼び出しで _ensure_index() が makedirs をもう一度試す` |
| `violates` | はい |
| (A)・(B)・(C) | (A)・(B) に数え、(C) に数えない（`失敗・期限切れ` は運用者が決める条件ではない） |

**理由**: 手引き 14.4 節の見分け方は「lifespan が初期化を**必ず**済ませるか（例外で抜けたら受付が始まらないか、条件つきではないか）も見る。条件つきなら、条件が偽のときはツールの呼び出しで届くので『到達する』」です。
元のサーバ A では、初期化が例外を投げれば lifespan ごと失敗し、受付が始まりません。
この変種では、22〜23 行で例外を握りつぶすので、初期化に失敗しても受付が始まり、`_index` は `None` のままです。
だから、ツールの呼び出しで 13 行の `makedirs` に届く道があります。
2 回目の `makedirs` が成功するかは、そのときの外の状態（ディレクトリの親が作られた、権限が変わった、など）によりますが、14.1 節は「起きる実行の道が 1 つでもあるか」を問うので、到達するとします。
条件の種類は、14.3 節の `失敗・期限切れ` の例（エラー時の後始末、再試行）に近いので `失敗・期限切れ` と書きました。外の状態の要素もあるので、`外部の状態` を重ねる読み方もありえます（どちらでも (B)・(C) の数は変わりません）。
