### 第 4 章

#### 演習 4-1（宣言を読む）

| | 当たる宣言 | 理由 |
|---|---|---|
| (a) | **D1** だけ | `readOnlyHint=True` があるので D1。`readOnlyHint: true` があると `destructiveHint` は意味を持たないので、`destructiveHint=False` は D2 にならない（4.2 節）。 |
| (b) | **D2・D3・D4** | `readOnlyHint: true` が無いので、`destructiveHint: False` は D2、`idempotentHint: True` は D4。`openWorldHint: False` は D3（D3 には `readOnlyHint` の条件は付かない）。 |
| (c) | **無し** | `title` は表示名で宣言ではない。`openWorldHint: True` は「外の世界と関わりうる」で、約束していない側の値。 |
| (d) | **D4** だけ | `readOnlyHint: False` は「変えうる」で約束ではないので D1 ではない。`readOnlyHint: true` が無いので `idempotentHint: True` は D4。 |
| (e) | **無し** | 注記を書いていない。既定値では「環境を変えうる（readOnlyHint false）・壊す更新をしうる（destructiveHint true）・繰り返すと追加の効果がありうる（idempotentHint false）・外の世界と関わりうる（openWorldHint true）」ツールとして扱われ、何も約束していない。 |

補足: (b) と (d) のように、`readOnlyHint` を明示の `False` にしても、書かなくても、D2・D4 を当てる点は同じ（「`readOnlyHint: true` が無いとき」）。

#### 演習 4-2（記録の範囲で言う）

| ツール | VS Code | Codex CLI |
|---|---|---|
| (a) `readOnlyHint=True` を含む | **確認を省く**。リリースノートに「`readOnlyHint: true` のツールは利用者の確認なしで実行される」とある [確認] | **承認を求めない**。`readOnlyHint` が true なら `return false`（承認なし）[確認] |
| (b) `readOnlyHint` が無く、`destructiveHint=False` | **記録に無い**。記録されているのは `readOnlyHint: true` のツールの扱いだけで、それ以外のツールをどう扱うかは書かれていない | **記録に無い**。`destructiveHint == Some(true)` の規則（承認を求める）にも、`readOnlyHint` が true の規則（承認なし）にも当たらない。どちらにも当たらないときの扱いは記録に書かれていない |
| (e) 注記なし | **記録に無い**。(b) と同じ理由 | **記録に無い**。`destructiveHint` も `readOnlyHint` も書かれていないので、どちらの規則にも当たらない |

考え方: 4.5 節の「つまずき」のとおり、記録に無いことを推測で埋めない。(a) だけが [確認] の記録から言える。(b)・(e) について「たぶん尋ねるだろう」と書くのは、確かめていないことを確かめたように書くことになる。

#### 演習 4-3（裏方の書き込みを見分ける）

**1. 何を書き換えるか**

- (a) 初回だけ、`~/.notes_app` というフォルダを作る。
- (b) `search.log` の末尾に、検索語を 1 行書き足す。
- (c) `cache.txt` の中身を消して、今回の検索の結果で上書きする。
- (d) 新しい一時ファイルを作って結果を書き、要約を作った後で消す。

**2. D1 に反するか**: (a)〜(d) のすべてが**反する**。この研究は宣言を字義どおりに読み、判定の手引きの D1 の表では「ファイルの書き込み・作成・削除・移動・権限の変更（`FS_WRITE` すべて）」が反する。注意の欄に「ログ・キャッシュ・一時ファイル・ディレクトリの作成も含む」とある（`docs/drafts/final_judging_guide_draft.md:309`）。(d) の一時ファイルは呼び出しの終わりには消えているが、D1 では作成も削除も反する（v4 の M58 と同じ形。同 `:641`）。到達するかは別の問い（(a) は初回だけ起きる条件つきで、条件の種類は `初回`。第 49 章）。

**3. 書き込み先の種類**

| | 種類 | 理由 |
|---|---|---|
| (a) | キャッシュ・状態の保存 | 初回に作る作業ディレクトリ |
| (b) | ログ | 記録のためだけに書き、ツールの動作では読み返さない |
| (c) | キャッシュ・状態の保存 | 13 行目で次の呼び出しが読み返す |
| (d) | 一時ファイル | 同じ呼び出しの中で作って消す |

（定義は `docs/drafts/final_judging_guide_draft.md:382-395` の 16.1 節。最終評価では、正にした組に 1 つだけ付ける。第 51 章。）

**4. 宣言が D2 だったら**: 反するのは **(c) だけ**。

- (a) フォルダを新しく作るだけ → 反しない（新しく作るだけ）。
- (b) `"a"` の追記 → 反しない（前からある中身は残る）。
- (c) 同じ `cache.txt` を毎回 `"w"` で書き直す → 前の呼び出しが書いた内容を上書きするので**反する**（手引きの 15.2 の「キャッシュの上書き」。`docs/drafts/final_judging_guide_draft.md:345-346`）。
- (d) 同じ呼び出しで自分が作った一時ファイルを消す → 反しない（解析器が矛を出していれば、判定は誤で原因 E2）。

D1 では 4 つとも反するのに、D2 では 1 つだけになる。判定は宣言ごとの問いで決まる。

#### 演習 4-4（D2 の判定の練習）

| | 判定 | 理由 |
|---|---|---|
| (1) | **反する** | 書き先 `path` を LLM が決められる。既存のファイルを指せば、`"w"` で中身が消えて上書きされる（原理 3-a）。 |
| (2) | **反しない** | `"x"` は「新しく作る」モードで、ファイルが既にあれば失敗する。前からあるものを壊さない。 |
| (3) | **反しない** | 書き先は固定のフォルダで、ファイル名は `uuid4()` で毎回新しくなる。呼び出しの前からそこにファイルがあることは、ふつう無い（手引きの「呼び出しごとに新しい名前なら反しない」）。 |
| (4) | **反する** | 消すのは前の呼び出しが書いたファイルで、呼び出しの前からあったもの。 |

#### 確認問題 4-1

反している。`destructiveHint: false` は「追加するだけで、今あるものは壊さない」という宣言なので、既存のファイル（呼び出しの前からあったもの）を消すのは違反。

#### 確認問題 4-2

MCP の既定値では、readOnlyHint は false、destructiveHint は true、idempotentHint は false、openWorldHint は true として扱われる。つまり「環境を変えうる・壊す更新をしうる・繰り返すと追加の効果がありうる・外の世界と関わりうる」ツールで、何も約束していない。

AuthGap はそれを宣言として数えない。解析器は既定値を補わず、作者がはっきり書いた宣言だけを取り出す（仕様書「annotation の不在は『非破壊の宣言』ではない」、`AUTHGAP_BRIEF_v3.md:316`）。最終評価の分母 (c) も、その宣言を明示的に書いた（`D_kind.explicit`）ユニットを持つ木だけを数え、既定値で補ったものは数えない（D70 の 4、`docs/decisions.md:3860`）。理由は、何も約束していないツールを「約束した」と数えると、「宣言を書いたサーバのうち」という問いに答えられなくなるから。なお、既定値はどれも D1〜D4 の反対側の値なので、既定値を補っても D1〜D4 は生まれない。

#### 確認問題 4-3

VS Code（Copilot のエージェントモード）は、`readOnlyHint: true` と注記されたツールを、利用者の確認なしで実行する。v1.100 のリリースノートにそう書いてある **[確認]**（`docs/incidental_writes_practice.md:96`）。

「すべてのクライアントが確認を省く」と書けない理由:
- [確認] は VS Code と Codex の 2 つだけで、ほかは [agent]（本記録者が原文と照合していない）。
- Gemini CLI は既定では自動で許可しない、という反対向きの報告がある [agent]。
- Claude Code は公式文書に記述が無く、第三者の報告も食い違う [未確認]。
- クライアントの動きは版で変わりうる（調査は 2026-09-29 の時点）。

#### 確認問題 4-4

反する。書き先 `path` を LLM が決められるので、LLM は既存のファイルを指すこともできる。指せば `open(path, "w")` でそのファイルの中身が消えて上書きされ、前からあったものが壊れる。モデルが決める値は取りうる値の全体で考える（第 17 章の原理 3-a）ので、D2 に反すると判定する（`docs/drafts/final_judging_guide_draft.md:335`）。
