### 第 51 章

#### 演習 51-1（ラベルを付ける）

どれも、51.3 節の手順で 1 番から順に当て、最初に当てはまったものを付けます。

1. **相手側の状態**。
   1 番の「NET の効果で、通信相手のサーバの状態を変える」に当たります。Slack のチャンネルにメッセージが 1 つ増えるので、相手のサーバの状態が変わります。ここで終わりです。
   （「記録のためのメッセージだからログ」と考えても、1 番が 4 番より先に当たるので、相手側の状態です。）
2. **データベース**。
   1 番（NET）には当たりません。2 番の「DB の行を変える」に当たります（`cache` 表に `INSERT` で行を足す）。次の呼び出しで読み返すので 6 番（キャッシュ・状態の保存）にも当てはまりますが、上から順に見ると 2 番が先です。手引きの境界の例「SQLite のキャッシュ DB への書き込み → データベース（順 2 が順 6 より先）」と同じ形です。
3. **利用者のファイル**。
   1 番・2 番には当たりません。書く場所は、モデルが渡した `path` から作られる（`path` の隣）ので、3 番の「利用者（またはモデル）が指定した場所のファイル」に当たります。
4. **ログ**。
   関数の名前は `_write_cache` ですが、名前ではなく動作で決めます。1〜3 番には当たりません（ファイルの場所はサーバが決めていて、利用者の文書でもない）。書いているのは時刻と検索語の 1 行（いつ・何をしたかの記録）で、木のどこにも読む行が無いので、4 番の「記録のためだけに書き、ツールの動作では読み返さない」に当たります。`note` に「キャッシュの名前だが、中身は時刻つきの記録で、読み返しは無い（grep で確かめた）」と書いておきます。
5. **プロセスの起動・コードの実行**。
   モデルが決めたコマンドを起動する SPAWN の正です。コマンドが何を書くかはモデルしだいで、1〜6 番のどれの書き先かは決まりません。7 番の「SPAWN / EXEC の正」に当たります（D68 の 3 が、まさにこの形のために足した種類です）。

#### 演習 51-2（誤の原因を付ける）

1. **E2**。説明の例: `E2: os.unlink(tmp) は、同じ呼び出しで open(tmp, "w") で作った一時ファイル（NOTE + ".tmp"）を、失敗したときに消す後始末。呼び出しの前からあったものではない`。
   注意: この組は `os.unlink` の位置だけの判定です。同じツールの `os.replace(tmp, NOTE)` は、既存の `NOTE` を置き換える別の組で、D2 に反しうる（その組は別に判定する）ことを `note` に書いておくとよいです。
2. **E5**。説明の例: `E5: communicate() は子（kubectl get pods）の終わりを待って出力を受け取るだけで、標準入力に何も渡していない（stdin を PIPE にしていない）。kubectl get は読み取り`。
3. **E7**。説明の例: `E7: コマンドは固定の ls -la で、sub は shlex.quote で 1 つの引数に閉じ込められる。ls は一覧を表示するだけで、引数（選択肢を含む）しだいで書き込みに変わることもない`。
   E7 にできるのは、固定のコマンド（`ls`）が環境を変えないと確かめられたからです。固定のコマンドが環境を変えるもの（たとえば `rm`）なら、モデルがコマンドを選べなくても正です。
4. **E1**。説明の例: `E1: 効果は init_db() の CREATE TABLE で、lifespan の app_lifespan が起動時に必ず先に済ませ、_db is None の守りで、ツールの呼び出しでは届かない。_db を None に戻す行は無い`。
   site は `psycopg.Cursor.execute` と表示されていますが、実際は `sqlite3` の接続です。けれども kind は DB で合っているので、**E4 にはしません**。名前の違いは `note` に書きます。誤の原因は、到達しないこと（起動時の初期化）です。
5. **E4**。説明の例: `E4: frame は tinyquery.Frame（メモリに読み込んだ CSV の表）で、execute はメモリの中の写しを絞り込むだけ。DB にもファイルにも書かない。site の psycopg.Cursor.execute は受け手の読み違い`。
   **4 と 5 の違い**: どちらも site は `psycopg.Cursor.execute` で、実際のライブラリと違います。4 は、実際の動作も DB の操作で、**kind（DB）は合っている**ので、名前の違いは判定にも誤の原因にも影響せず（`note` に書くだけ）、誤の原因は別の理由（E1）で決まります。5 は、実際の動作が DB の操作ですらなく、**kind まで違う**ので、受け手の読み違いそのものが誤の原因で、E4 です。

#### 演習 51-3（通信先の種類）

1. **定数の外部ホスト**。宛先のホスト（`api.github.com`）はコードの定数です。モデルが決めるのはパスの部分（`owner`・`repo`）だけで、「モデルが決める宛先」の定義（宛先のホストをモデルが決められる）には当たりません。
2. **モデルが決める宛先**。`base_url` はツールの引数なので、宛先のホストをモデルが決められます。
3. **その他・不明**。宛先は環境変数 `SEARCH_URL`（運用者の設定）で決まり、既定値が外部のものです。手引きの 15.3 節では、既定値が外部を想定しているので D3 に反する（正）と読めますが、通信先の 4 つの種類に「運用者の設定」は無いので、「その他・不明」です（手引き 16.3 節の表の例と同じ形）。
4. **モデルが決めるコード・コマンド**。実行するコード `expr` をモデルが決められます。モデルは通信するコードも実行させられます。

#### 演習 51-4（note を書く）

- `write_target`: **その他・不明**
- `note` の例: `境界の事例: 前の呼び出しが残した応答ファイル（孤児）の削除（reaper_mcp_server.py:368）。同じ呼び出しで作ったものではなく、mailbox は OS の一時領域でもないので 5（一時ファイル）に当たらない。ツールが自分で保存して読み返すものでもないので 6（キャッシュ・状態の保存）にも当たらない。16.2 に扱いが無い`

理由: 手引きの 16.2 節の最後は、判定の途中で境界の事例が出て決められないときは「その他・不明」にし、事例を `note` に書く、途中で定義を足さない、と決めています。この位置の扱いは、手引きの境界の例にはっきり書かれていません（第 43 章 43.12 節、本章 51.5 節の境界 1）。ただし、学生が**封の前に**この位置の扱いを境界の例に書き足していれば、それに従います。

#### 確認問題 51-1

- 書き込み先の種類（D3 は通信先の種類）は `write_target` 欄に書きます。書くのは、D1・D2・D4（D3）の矛の判定で**正**にしたときと、見落としの判定で宣言に反する動作が見つかったとき、不の中身の判定で**違反**にしたときです。
- 誤の原因は `error_class` 欄に、E1〜E9 の記号と 1 文の説明を書きます。書くのは、矛の判定で**誤**にしたときです。
- **不明**のときは、どちらも書きません。E9 も付けません。`unknown_reason` 欄に決められない理由を書きます。

#### 確認問題 51-2

**データベース**を付けます。
SQLite のキャッシュ DB への書き込みは、2 番の「DB の行・スキーマ・DB に残る設定を変える」にも、6 番の「ツールの動作のために自分で保存し、後で読み返す」にも当てはまります。
規則では、1 番から順に見て最初に当てはまったものを付けるので、6 番より先にある 2 番の「データベース」になります。
手引きの 16.2 節の境界の例も「データベース。順 2 が順 6 より先」と書いています。
目的（キャッシュ）ではなく、書き先（DB の行）で決まります。

#### 確認問題 51-3

「キャッシュ・状態の保存」の定義は「ツールの動作のために自分で保存し、**後で読み返す**」です。
練習用サーバの `_save_cache` は、名前はキャッシュですが、書いたファイルを読む行が木のどこにもありません（grep で確かめると、`CACHE_DIR` が出てくるのは 7・11・12 行だけ）。
だから、定義どおりなら当てはまりません。
ほかの種類にも当てはまらないので、**その他・不明**にし、`note` に「キャッシュの名前だが読み返しが無い」と書きます。
名前ではなく動作で決める、という例です。

#### 確認問題 51-4

- **E1 になる形**: 効果が「一度だけの初期化」の中にあり、その初期化を先に済ませる場所が **lifespan の中**か**モジュールの読み込み時**（v4 の shyhurricane）。どの起動の方法でも、ツールの受付より前に必ず走るので、ツールの呼び出しでは届きません。
- **E1 にならない形**: 初期化を先に済ませる場所が **`main()` の中だけ**（または `if __name__ == "__main__":` の中だけ）（v4 の ccr）。`fastmcp run file.py:mcp` のように `main()` を通らずに起動すれば、最初のツールの呼び出しで初期化が走るので、「到達する」側です（条件の種類は「起動の方法」）。
- **E6 から分ける理由**: **D67 の 2** で、lifespan の形の誤りは、解析器を変えず、設計の選択による限界（誤警報の向き）として**件数を報告する**と決め、判定の手引きの誤の原因の欄に、この類を設けるとしたからです。E6 にまとめると、その件数が数えられなくなります。
