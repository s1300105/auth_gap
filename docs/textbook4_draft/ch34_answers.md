#### 演習 34-4（SHA と sha256 を使い分ける）

**(a)** **コミットの SHA**。取得した木で `git rev-parse HEAD` を実行し、その値を、段階 3 でコミットした pin の SHA と比べます。一致しなければ、その木は pin の版ではありません（浅い取得で既定のブランチの最新に落ちた、など）。中断した作業木は HEAD が一致しても中身が空のことがあるので、取得が最後まで終わったかも確かめます。

**(b)** **ファイルの sha256**。2 つの木の、ツールの定義を含む `.py` ファイルの sha256 を取り、比べます（D70 の 6）。repo が違えばコミットの SHA はふつう違うので、SHA では中身が同じかは分かりません。

**(c)** **ファイルの sha256**（を束ねた結合 sha256）。`authgap/` の全ファイルの sha256 から作った結合 sha256（`summary.json` の `implementation_sha256_combined`）を、`docs/fingerprint.json` の値（`35606ba9…`）と比べます。あわせて、`git diff analyzer-freeze-3 -- authgap/` が空であることも確かめます（後者は git のコミットとの比べ方です）。

**(d)**
- **pin の SHA は違います**。Y はフォークの後にコミットを 1 つ足したので、Y の既定のブランチの先頭のコミットは X のものと違います。
- **`server.py` の sha256 は同じ**です。中身が同じだからです。
- **Y は除かれます**。D70 の 6 は「今回の中の重複」について、ツールの定義を含むファイルが一致する木どうしは、repo 名（小文字）の辞書順で最初の 1 木だけを残すと決めています。X が先なので X を残し、Y を除きます。除いた木の数と、どの木と一致したかを記録し、補充はしません。README の違いは、ツールの定義を含むファイルではないので比べる対象に入りません。
