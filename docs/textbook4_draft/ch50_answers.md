### 第 50 章

演習のコードはすべて本書の作例です。
「解析器は〜」の答えは、本書の執筆時に、同じ形の作例を凍結版の解析器（`analyzer-freeze-3`）で走査して確かめたものです。
「人の答え」は、手引きの下書き（未承認）の規則を当てた本書の考え方の例です。

#### 演習 50-1（一時ファイルを、D1 と D2 で比べる）

(1) 10 行目の `os.remove` に、解析器は次を出します。
- ツール A（D1）: **矛**、理由 `fs_write`（D1 ではファイルの書き込み・作成・削除はすべて矛）。
- ツール B（D2）: **矛**、理由 `fs_remove`（D2 では削除は「既存のものを消す」類として矛）。

あわせて、6 行目の `open(path, "w")` は、ツール A では矛（`fs_write`）、ツール B では不（`fs_writeout`。書き先がモデルの値ではない書き出し）になります。

(2) 10 行目の組の判定:
- ツール A（D1）: 到達は `はい`（`finally` の中なので毎回）。D1 の問い「呼び出しの後に残る何かを変えるか」では、ファイルの作成・削除はすべて環境の変更で、一時ファイルも含みます（手引き 15.1 節、原理 1-i-b）。**反する → 正**。書き込み先の種類は **一時ファイル**（同じ呼び出しの中で作って消す。第 51 章）。
- ツール B（D2）: 到達は `はい`。D2 の問い「呼び出しの前からあったものを消すか」では、消すのは同じ呼び出しの 3 行目で自分が作った一時ファイルなので、前からあったものではありません。**反しない → 誤、E2**。`error_class` の例: `E2: 同じ呼び出しで mkstemp した一時ファイルを finally で消す（server.py:3,10）`。

(3) 8 行目の `subprocess.run(["wc", "-l", path])` は、先頭が定数の `wc` なので、解析器は D1 でも D2 でも **不**（`spawn_command`）にします。人が調べると、`wc -l` は行数を数えて標準出力に出すだけで、ファイルを書きません。D1・D2 とも**反しない**と答えます（この組は矛ではないので、矛の判定には出ません。不の中身や見落としの判定で出会ったときの答えです）。

(4) 前の呼び出しが残した `STALE_FILE` を消すなら、それは呼び出しの前からあったものです。ツール B（D2）でも**反する → 正**になります（手引き 15.2 節の「ただし前の呼び出しが残したファイルを消すなら反する」。v4 の reaper-mcp の M22 と同じ形）。ツール A（D1）は、もともと反するので正のままです。

#### 演習 50-3（毎回書き直すキャッシュ。D2）

(1) 5 行目の `os.makedirs(..., exist_ok=True)` は、D2 では「新しく作るだけ」の類なので **内**です。6 行目の `open(CACHE_FILE, "w")` は、書き先がモデルの値ではない書き出しなので **不**（`fs_writeout`）です。4 行目の `GET` は内です。

(2) D2 の**矛はありません**。だから矛の判定には出ません。6 行目の動作に人が答えるのは、次の 2 つの場面です。

- **見落としの判定**で、このツール（D2 を明示し、D2 の矛が無い）が選ばれたとき。このときは解析器の出力を見る前に本体を読み、6 行目を「反しうる動作」として書き出し、その後で出力の `contradiction_unknown:D2:fs_writeout` を見て、結果を「解析器が不として出している」にします。

1. 名前は毎回同じか → はい（1 行目の定数）。
2. 前の呼び出しがそのファイルを残すか → はい（消す行が無い。grep で確かめる）。
3. 書く前にファイルがあるかを確かめているか → いいえ。
4. （ほかの誰かが置くか → この問いに答えなくても、1〜3 で決まる。）

1 回目の呼び出しの後はファイルが残り、2 回目からは前の内容を消して書き直します。前からあったものを上書きするので **反する**（違反）です（手引き 15.2 節の「キャッシュの上書き」）。

#### 演習 50-4（環境変数の URL へ `GET` する。D3）

(1) 解析器は、運用者の設定（環境変数）の値を読めないとして、D3 の **不**（`net_host_unknown`）を出します（本書の試験で、`os.environ.get` の既定値つきの形は不でした）。

(2) 手引き 15.3 節の「宛先が運用者の設定で決まる」の行を当てます。既定値が `https://search.example.com/api` で外部を想定しているので、**反する**と答えます。

(3)
- 既定値が `http://localhost:9200` なら、手元を想定しているので **反しない**です。
- 既定値が無く、README などの文書にも説明が無ければ、どこを想定しているか分からないので **決められない**です（理由を書いて不明）。`.env.example`・`docker-compose.yml` なども探し、そこに外部か手元の例があれば、それで決めます。

(4) **ありません**。最終評価では、D3 を人が判定するのは矛の判定だけで、D3 の不は件数と理由だけを報告します（D69 の 4）。D3 には見落としの判定もありません（見落としは D1・D2 だけ）。だから、(2)(3) の答えは、手引きの規則の練習としての答えで、最終評価の数字には入りません。

#### 確認問題 50-1

D2 の問いは「呼び出しの前からあったものを上書きするか」で、原理 3-a により、モデルが選べる `path` は取りうる値の全体で読みます。モデルが既存のファイルを指せば上書きできるので、**D2 には反します**。
D4 の問いは「**同じ引数で** 2 回呼んだとき、2 回目がさらに変えるか」です。同じ `path`・同じ `content` で 2 回呼べば、2 回目は同じ中身を同じ場所に書くだけで、状態は 1 回目の後と同じです。繰り返しの間は引数が同じと決まっているので、引数の取りうる値の範囲は関係しません。だから **D4 には反しません**（§7.0 の 1、手引き 15.4 節）。

#### 確認問題 50-2

- **D1**（呼び出しの後に残る何かを変えるか）: 相手のサーバに新しいメッセージが残るので **反する**（作成も環境の変更。原理 1-ii-b）。
- **D2**（前からあったものを消す・上書きする・変えるか）: 新しいメッセージを足すだけで、前からあったものは変えないので **反しない**。
- **D4**（同じ引数で 2 回呼んだとき、2 回目がさらに変えるか）: 同じ文で 2 回送れば 2 通になるので **反する**（相手の API がそういう意味なら。手引きは「相手の API の意味で決める」）。

分かれる理由: 3 つの宣言は問いが違うからです。D1 は「変えるか」、D2 は「前からあるものを壊すか」、D4 は「繰り返しでさらに変わるか」を問うので、同じ「新しく作る」動作でも答えが違います。

#### 確認問題 50-3

D3 と D4 について人が判定するのは、**矛の判定**の場面だけです（不の中身と見落としの判定は D1・D2 だけ。D69 の 3・4、手引き 18.1・18A.1 節）。
- D3 の矛の組: 理由が `net_external_host`（定数の外部ホスト）・`net_model_host`（モデルが決める宛先）・`exec_model`・`spawn_model`（モデルが決めるコード・コマンド）の 4 つのどれかの組。
- D4 の矛の組: 理由は **`fs_append`** だけです（`open` の仲間で、モードの定数に `a` が入っている行）。だから D4 の判定は、毎回書き足すか（正）、書く前に確かめるか・開くだけで書かないか（誤、E8）を見分けることになります。

#### 確認問題 50-4

`violates` 欄は **`決められない`**、結果（`outcome`）は **`不明`** です。`unknown_reason` には「手引き 15.2: DB に残る設定の変更は『追加か破壊か』が当てはまらない」と書きます。
理由: D2 の問いは「追加の更新だけか（前からあるものを壊さないか）」で、`PRAGMA journal_mode=WAL` はデータを足すのでも消すのでもなく、DB の設定を変えるものです。問いの物差しが当てはまらないので、手引きは「不明（解析器と同じ）」と先に決めています。調べても答えは変わりません。（D1 なら「変えるか」で答えられるので反します。）
