#### 演習 29-2（相対 URL の宛先）

| | `url.host` | `url.path` | D3 の答え |
|---|---|---|---|
| (a) | 主体 `OP`・定数 `"https://api.example.com"`（`base_url` から取った） | 主体 `MODEL` | **矛**（理由 `net_external_host`。定数の外部ホスト） |
| (b) | 主体 `OP`・確度 `opaque(unresolved)`（`base_url` が読めない） | 主体 `MODEL` | **不**（理由 `net_host_unknown`。宛先が読めない） |
| (c) | 主体 `MODEL`・確度 `resolved`（`"/" + path` は分けないので、値の全体） | 無し | **矛**（理由 `net_model_host`。宛先をモデルが決められる） |

本書の執筆時に、3 つをそれぞれ `openWorldHint: False` のツールにして走らせ、表のとおりの注記を確かめました（(b) の `settings` は、木の中に定義の無いモジュールから import した）。

- (a) は、O32 の直しどおり、相対 URL をパスとして読み、宛先は `base_url` から取りました。宛先が定数の外部ホストなので、関わる範囲が閉じているという宣言に反します。モデルが変えられるのはパスだけですが、それとは関係なく、ツールは外部のホストと通信します。
- (b) は、相対 URL なので宛先は `base_url` から取りますが、`base_url` の値（設定ファイルから読む値）を解析器が読めないので、宛先は「読めない」になり、不です。人が判定するなら、設定ファイルや環境変数を調べて、宛先が外部か、同じ機械の上かを確かめます。
- (c) は、先頭が `"/"` だけなので分けません。モデルが `"/evil.example/x"` を渡すと `"//evil.example/x"` になり、宛先が変わりうるからです（誤 clear を作らないための例外）。`base_url` が `127.0.0.1`（同じ機械）でも、宛先をモデルが決められるとして矛になります。

（出典: `authgap/effects.py:494-498, 544-548`、`docs/contradiction_principles.md:283-294`（§9.2）、`:202-212`（§7.3 の D3 の表））

#### 演習 29-3（流れ込むと選べる）

**(1)**

| | `argv0` の主体・確度 | D1 の答え | 理由 |
|---|---|---|---|
| (a) | `MODEL`・`resolved` | **矛** | `spawn_model`（モデルが起動するプログラムを選べる） |
| (b) | `MODEL`・`opaque(unresolved)` | **不** | `spawn_model_opaque`（モデルの値が流れ込むが、選べるとまでは読み切れない） |

(a) では、`cmd` がそのまま列の 1 番目の要素になるので、モデルが起動するプログラムを選べます（確度 `resolved`）。原理 3 a で、モデルが選べるなら、どんなプログラムでも起動できる、と読み、読むだけの宣言に反するので矛です。
(b) では、`cmd` が木の外のライブラリの関数 `normalize_command` を通るので、解析器はその中を読めず、確度が `opaque` になります。だから不です。
本書の執筆時に、(a)・(b) を `readOnlyHint: True` のツールにして走らせ、注記が `contradiction:D1` と `contradiction_reason:D1:spawn_model`、`contradiction_unknown:D1:spawn_model_opaque` になることを確かめました。

**(2)** 手引きの 18A 節は、`…_opaque` の不について「モデルの値が書き先・宛先を選べるところまで届くかを、値の流れをたどって確かめる」と書いています（`docs/drafts/final_judging_guide_draft.md:510`）。
(b) なら、`normalize_command` の中身（ライブラリのコードや文書）を調べ、

- モデルの値をそのまま（あるいは形を整えるだけで）返すなら、モデルは起動するプログラムを**選べる**。原理 3 a で取りうる値の全体を考え、読むだけの宣言に反するかを決める（どんなプログラムでも起動できるなら、反する）。
- 決まった候補の中のどれかに置き換える、候補に無ければ止める、という関数なら、モデルが選べるのは**その候補の中だけ**。候補のそれぞれが何をするかを調べる。

を確かめます。
20〜30 分調べても決められなければ「不明」にし、理由を書きます（手引きの第 19 節）。

**(3)** モデルは、`ALLOWED` の中の 2 つ（`/bin/ls` と `/bin/pwd`）のどちらかを**選べます**。けれども、それ以外のプログラムは選べません（`ALLOWED` に無いキーを渡すと、`KeyError` で止まり、起動しません）。
原理 3 a の「取りうる値の全体」は、`{"/bin/ls", "/bin/pwd"}` の 2 つです。
次に、2 つのプログラムがそれぞれ何をするかを調べます。
`ls`（ファイルの一覧を表示する）と `pwd`（今のディレクトリを表示する）は、どちらも何も書き換えないので、読むだけの宣言には反しない、と判断できます（ただし、引数が無い形で起動していることも確かめます）。

参考までに、凍結版の解析器は (c) の `argv0` を主体 `OP`・確度 `opaque(unresolved)` と読み、D1 の答えは**不**（理由 `spawn_command`、コマンドの意味が名前から分からない）でした（本書の執筆時に確かめた）。
解析器は「どれを選べるか」までは読みませんが、人は辞書の中身を読んで、選べる範囲を決められます。

#### 確認問題 29-2

モデルが、パスの代わりに `"/evil.example/x"` のような値を渡すと、`"/" + "/evil.example/x"` は `"//evil.example/x"` になるからです。
`//` で始まる URL は、`urljoin` のような関数では「ホストから書いた URL」と解釈され、宛先が `evil.example` に変わってしまいます。
これを「パスだから宛先は変わらない」と読むと、宛先をモデルが変えられるのに問題なしとする**誤 clear** を作ります。
そこで、`"/"` だけや `"//"` で始まる形は分けずに、値の全体を宛先として読みます（`docs/contradiction_principles.md:291-293`）。

#### 確認問題 29-3

`select(Item).where(Item.id.in_(ids))` では、モデルの値 `ids` は SQL の中に**入って**います（流れ込む）。
けれども、`ids` はバインド変数（SQL の文とは別に、安全に渡される値）として渡されるだけで、SQL の**命令の種類**（`SELECT` か `DELETE` か）は、コード（`select(...)`）が決めています。
モデルは、`ids` に何を渡しても、`DELETE` の文を書くことはできません（**選べない**）。

解析器は、この 2 つを**確度**で区別しています。
主体が `MODEL` で確度が `resolved`（モデルの入力が、解析器のモデリングした操作だけを通って届いた）なら「選べる」、主体が `MODEL` で確度が `opaque`（中の分からない関数を通った）なら「流れ込む（だけかもしれない）」です。
後者は、判定表で不になり、理由の末尾に `_opaque` が付きます（`authgap/dparse.py:245-272` の `_choice` と `_by_choice`）。

#### 確認問題 29-4

理由 `fs_writeout_model_path_opaque` は、「D2（壊さない）について、ファイルの書き出し（`write_text`・`open('w')` など）の書き先 `path` に、モデルの値が流れ込むが、モデルが書き先を選べるとまでは読み切れない」という不です。
判定では、次のことを確かめます（手引きの 18A 節）。

1. **到達するか**: ツールが呼ばれたとき、その書き出しが起きる実行の道が 1 つでもあるか（第 49 章）。
2. **モデルが書き先を選べるか**: 書き先の値が、ツールの引数（モデルの値）から、どんな関数を通って届いているかをたどり、モデルが書き先を**実際に選べる**ところまで届くかを確かめる（`…_opaque` の調べ方。`docs/drafts/final_judging_guide_draft.md:510`）。途中で決まったディレクトリの下に限られる、名前を整えるだけ、などの形を見分ける。
3. **宣言に反するか**: モデルが既存のファイルを書き先に選べるなら、上書きできるので、壊さないという宣言に反する（原理 3 a）。モデルが選べず、書き先が呼び出しの前から存在しうるか（上書きか新規作成か）も分からないなら、書き先にファイルが前からありうるかを調べる（手引きの 15.2 節、`fs_writeout` の調べ方）。

到達し、かつ宣言に反するなら「**違反**」、到達しないか宣言に反しないなら「**違反でない**」、20〜30 分調べても決められなければ「**不明**」です。
違反なら、書き込み先の種類（第 16 節）と条件の種類も付けます。
