#### 演習 43-3（クライアントの確認の省略）

1. 例: **VS Code**（Copilot のエージェントモード。v1.100 のリリースノートに、`readOnlyHint: true` のツールは利用者の確認なしで実行されるとある）[確認]。**OpenAI Codex CLI**（`requires_mcp_tool_approval` が、`readOnlyHint` が true なら承認を求めない）[確認]。ほかに Goose・Claude の connectors・GitHub Copilot coding agent [agent]。Gemini CLI は既定では自動承認しない [agent]、Claude Code は [未確認]。
2. **D68 の 1**（条件つきで届く効果）の理由に使われています。「クライアントは `readOnlyHint: true` を見て呼び出しごとの確認を省く。確認を省いたどれか 1 回で起きるなら宣言は守られていない」。だから、毎回でなくても、ツールの呼び出しで届きうるなら「到達する」とし、条件の種類を記録して (B)(C) を併記します。D67 の 2（起動時の初期化）も同じ「届きうる」の読み方です。
3. 手順書 24.3 節は、違反の意味づけにこの事実が使えるとし、書き込み先の種類の内訳と合わせて「**確認を省かれた呼び出しで何が書き換わるか**」として示せる、と書いています。つまり、内訳の表を「確認なしで呼ばれたときに、利用者のファイル・DB・相手側の状態・ログ・一時ファイルなどが何件書き換わりうるか」として読ませることで、読み手が軽重を自分で判断する材料になります。
   この問いへの関わり: クライアントは書き込みの種類で区別しないので、裏方の書き込みも本来の書き込みも同じように確認なしで起きます。だから「裏方なら違反でない」と研究の側で線を引く理由は、ここからは出てきません。

#### 確認問題 43-1

MCP の仕様は、裏方の書き込みについて**何も言っていません**。
schema の `readOnlyHint` の説明は "If true, the tool does not modify its environment."（既定は false）の 1 文だけで、「環境」の定義も例もありません [確認: draft]。
仕様の本文・公式ブログ・SEP にも、ログ・キャッシュ・一時ファイルの扱いはありません。
ToolAnnotations を入れた PR #185 の途中の案は、"does not perform writes or updates, or otherwise change server-side state in ways that would be visible in subsequent tool calls."（後の呼び出しで見える形でサーバの側の状態を変えない）で、観測できるかを基準にしていました。
最終の文言は "does not modify its environment" に変わり、「後の呼び出しで見える形で」という限定が無くなりました。
変えた理由は見つかっていません [agent。理由は不明]。

#### 確認問題 43-2

「定義と検査器を分ける」とは、約束の**定義**では付随的な書き込みを許しても、それを確かめる**検査器**は、見分けられないものを保守的に拒む、という考え方です。
Checker Framework の `@SideEffectFree` は、定義では「見える副作用だけが問題」とし、新しく作ったオブジェクトを変えるのも許します。
けれども検査器は、"a method that caches its result will be rejected"（結果をキャッシュするメソッドは拒まれる）[確認]。
キャッシュが本当に見えないかは使われ方全体により、静的には確実に判定できないからです。
AuthGap も同じ形で、解析器は裏方の書き込みも矛にし（保守的な検査器）、人が判定して、正には書き込み先の種類のラベルを付けます。
ただし MCP には「環境」の定義が無いので、AuthGap は定義そのものも字義どおりに読みます。

#### 確認問題 43-4

宣言ごとに問いが違うからです。
D1（`readOnlyHint: true`）の問いは「環境を変えるか」で、一時ファイルの作成・削除もファイルシステムへの書き込みなので**反します**（判定表 §7.1 の FS_WRITE すべて → 矛、手引き 15.1 節。v4 の M58 も正）。
D2（`destructiveHint: false`）の問いは「**呼び出しの前からあったもの**を消す・上書き・変えるか」で、同じ呼び出しで自分が作った一時ファイルを消すのは、前からあったものではないので**反しません**。
解析器がこれを D2 の矛にしていたら、判定は誤で、誤の原因は **E2**（同じ呼び出しで作った一時ファイル・ロックの後始末）です。
ただし、前の呼び出しが残したファイルを消すなら、D2 でも反します。
