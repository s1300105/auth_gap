## 確かめること（手続きと分母）

- **V1 頑健性**: parse 失敗・tree budget で打ち切った木・例外で落ちた木を全件列挙し、原因を 1 件ずつ書く。
  分母は走査した木の数。
- **V2 CONTRADICTION の精度**: 単位は (木, ユニット, site, kind, 宣言)。**D1 / D2 の矛は全件**判定する
  （60 件を超えたら seed 20260924 で 60 件を抜き取り、抜き取りと明記する）。D3 / D4 の矛は別に
  30 件まで（同じ seed）。判定は原ソースを読み、`docs/contradiction_principles.md` §6 の採った原理で:
  - **正**: その経路は実行時に到達し、その動作は宣言に反する。
  - **誤**: 到達しない / 動作が宣言に反しない / 解析器が読み違えた（原因の分類を書く）。
  - **不明**: 静的に決められない（理由を書く。黙って正・誤に倒さない）。
  分母は判定した件数。正 / 誤 / 不明の件数と、誤の原因の内訳を出す。
- **V3 見落としの抜き取り**: v3 で D1 か D2 を明示し（`D_explicit`）、その宣言に対する矛が 1 件も出て
  いないユニットから **seed 20260924 で 30 件**を抜き取る。ツールの本体と、木の中の呼び出し先を深さ 4
  まで読み、宣言に反する動作があるかを判定する: 解析器が不として出している / **見落とし（誤 clear）** /
  反する動作は無い / 不明。分母は 30（足りなければ全数）。
- **V4 不（静的に決められない）**: 件数と理由の内訳だけを出す（判定しない）。

## 結果（2026-09-24、`scan_v2_v3_run1`、`analyzer-freeze-1`）

判定は本記録者（原ソースの確認は木ごとにエージェントに分け、根拠のファイルと行を見直して採った。M19・M10・R11 は
本記録者が原ソースで確認）。判定の詳細は `evidence/population_v3/v2_judgments.json` と `v3_miss_judgments.json`。

**V1 頑健性**（分母 91 木）: 91 木すべて ok、tree budget の打ち切り 0。parse 失敗 8 ファイル（4 木）はすべてファイル自体の
構文エラー（うち 1 つは Python 3.14 の `except A, B:`）で、MCP サーバ本体ではない。

**V2 矛の精度**（D1 / D2 は母数 86 から 60 件を抜き取り、D3 / D4 は全 3 件）:

| | 判定 | 正 | 誤 | 不明 |
|---|---|---|---|---|
| D1 / D2 | 60 | **49（81.7%）** | 11 | 0 |
| D3 / D4 | 3 | 2 | 1 | 0 |

誤の原因: 子プロセスの標準入力への `communicate(input=None)` を FS_WRITE にする 4、ツール自身が同じ呼び出しで作った一時
ファイルの削除を破壊的とみなす 3、末尾名だけの解決（ローカルの `bytearray.append` を木の中の `AuditLog.append` に結ぶ）で
矛にする 2、固定のコマンドに `shlex.quote` した値だけを渡す spawn をモデルが決めるコマンドとみなす 2。D4 の 1 は `flock`
のために `"a"` で開くだけ。正のうち、初回の DB 作成・移行時だけの書き込みによるもの（lore・synapse-s2 の 16 件）は条件つき。

**V3 見落としの抜き取り**（D1 / D2 を明示し矛の無いユニット 771 から 30 件）: 反する動作が無い 21、**見落とし 7**、不明 2。
見落としの原因: 呼び出しの解決 3（関数が返すモジュール 1、パッケージの `__init__.py` の再公開 2）、深さの上限 2（深さ 5 と 7）、
受け手の型（ヘルパの戻り値の注釈 `-> httpx.AsyncClient`）1、sink の語彙に無いライブラリ（zvec の `upsert`）1。
見つかっていれば矛になったのは 5（うち 1 は深さ 7 の条件つき）、不が 1、弱いものが 1。

**構造的な所見**: 呼び出しを解決できなかったツールは、宣言に対して何の印も残さず「矛盾なし」に見える（規則 4 の「黙って
安全側に倒す」形）。ただし一律に不明にはできない: D1 / D2 を明示したユニットのうち何らかの未解決を持つものは run18 で
1,026 / 1,036、v3 で 846 / 859。同様に、確度 `opaque(unresolved)` の効果だけに支えられた矛は run18 で 114 / 190、v3 で
64 / 89 あるが、v3 の判定での誤はそのうち 2 だけで、一律に不へ落とすと正しい矛の大半を捨てる。
