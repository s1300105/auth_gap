## 段階 A: 判定を身につける

### A1. 判定の方法を理解する【学生】（3〜8 時間）

**ねらい**: 1 件の判定で答えるのは 2 つの問いだけ、と分かること。
- 問い 1: **届くか** — ツールを呼んだら、効果の行（書く・消すなど）まで処理が進むか（値がどこから来たかは問わない）。
- 問い 2: **宣言に反するか** — その動作が宣言（D1 読むだけ / D2 壊さない / D3 外と関わらない / D4 何度でも同じ）と食い違うか。

**読む順**（`docs/textbook/` の下）:
1. 第 48 章 48.2「2 つの問いと 5 行の判定表」、48.14「通しの例」（30 分）。48.2 の「2026-10-06 に追記」の段落は、A3 で決める点（8〜11）
2. 付録 I-1（正になる例）→ I-2（誤になる例）を、例を 3〜4 個読んだら練習問題を 1〜2 問、のくり返しで（各 1〜2 時間）
3. 付録 I-3（条件とラベル）、I-4（不明と不の中身）（各 1 時間）
4. 迷ったら付録 H（手引きの 1 行ずつの解説）を節の番号で引く

**終わりの目安**: 付録 I の練習問題の 7 割ほどが、答えを見ずに合う。

### A2. 練習で判定し、1 件の時間を測る【学生】（半日〜1 日）

**材料**: `evidence/practice_v4/`（手順は同じフォルダの `README.md`）。

1. `cd ~/research/auth_gap && git pull`
2. 練習の 6 木を取る（初回だけ）:
   ```bash
   .venv/bin/python scripts/fetch_corpus.py --spec evidence/practice_v4/fetch_spec_practice.json
   git restore docs/frame.csv docs/fetch_failures.md
   ```
3. `contradiction.csv` の `seq` 2（P-C03）から順に判定する（P-C08 は本記録者のお手本なので除く）。
   - **始める前に時刻をメモし、`minutes` に分数を書く**（手順 A から記録を書き終えるまで。休憩は除く）。
   - 横に `path_view/P-Cxx.txt` を開き、`★`（効果の行）から上へ `?`（条件の行）だけを拾って読む。
   - 分からない関数は、AI に**事実だけ**を聞いてよい（repo を知らない新しい会話、宣言の部分を消して貼る、`ai_used` を書く）。
   - 20〜30 分調べても決められなければ `不明` にして理由を書く。
4. 時間があれば `miss.csv`（見落とし 3 件、P-M01〜P-M03）も同じように判定し、分数を測る。**実態調査の 1 件は見落としの判定と同じ
   重さ**（解析器の出力を見ずに深さ 4 まで読む）なので、この分数が実態調査の件数（B1）を決める目安になる。
5. 終わったら `answers_v4_DO_NOT_OPEN_FIRST.md` と見比べる（本記録者の判定で正解ではない）。
6. **本記録者に送る**: 1 件ごとの分数、迷った箇所（手引きの節の番号）。

**最低限**: 3 件でも時間が分かれば B1 に進める。

### A3. 手引きの曖昧な点を決める【学生】（30 分）

付録 I の表紙「手引きが決めていない点」の 13 個（8〜11 は 2026-10-06、12・13 は 2026-10-07 に足した）と、A2 で迷った点を、本記録者が選択肢つきの短い表にする。
学生が選ぶ（「推奨どおり」でもよい）。本記録者が決定として `docs/decisions.md` に記録し（D83 以降の番号）、手引きに書き足す。

## 段階 E: まとめる

### E1. 集計【本記録者】

実態調査（事前登録の下書き (f2)）と見落とし（D2）の集計は、B2 で `final_aggregate.py` に足してから使う。

```bash
.venv/bin/python scripts/final_aggregate.py --run evidence/scan_v2_final_run1 \
    --contradiction-sample … --unknown-sample … --contradictions … --unknowns … \
    --second-contradictions …（D2 の結果） --seed <④> --out-json … --out-md …
```

出すもの（宣言ごと、合算しない）:
- **実態**（D1）: 違反の割合と Wilson 区間、(B)(C)、書き込み先の種類の内訳。解析器との突き合わせ（無作為な標本での再現率、
  ツール単位の精度、D1 の不の中身）。事前登録の下書き (f2)
- **精度**: 木ごとの精度の平均と区間（木を単位にした bootstrap）、件数の精度と Wilson 区間、不明の数と「不明を誤とみなした値」
- **誤の原因**の内訳（E1〜E9）、正の**書き込み先の種類**と**条件の種類**の内訳、(B)(C)（下限）
- **不の中身**: 不のうち本当の違反の割合
- **判定の一致**: κ と一致率
- **再現率**（済み）: `evidence/annotation_fixes_frame/recall_run1.json`・`baselines_run1.json`・`recall_d0_run1.json`
- **頑健性**: 打ち切り・parse の失敗・メモリ超過で除いた木、深さ 3・5 の件数

### E2. 見落としの原因の分析【学生＋本記録者】（任意、1〜2 日）

再現率の評価で「なし」になった件から 1 群 1 件（約 40 件）を見て、**本当の見落とし**（語彙・入口・呼び出しの解決など）か
**開発者が安全側に付け直しただけ**かを分ける。考察の節が厚くなる。
