元の一覧は `docs/textbook/appendix-i.md` の表紙「手引きが決めていない点」の 1〜13。加えて、第 10〜56 章の見直し（2026-10-06）で
見つかった 3 点を 14〜16 として足した。**どれも最終評価のデータを見る前に決める。** 決めたら本記録者が決定として記録し
（`docs/decisions.md`）、手引きの下書きに書き足し、付録 I・教科書の該当の箇所を直す。

「影響」の列: **正誤** = 判定（正・誤・不明）が変わる。**内訳** = 条件の種類・書き込み先の種類・理由の類など、報告の内訳だけが変わる。
**記録** = 書き方だけが変わる。

推奨の決め方は D76 と同じ: 手引きの今の文から筋が通る側、前に決めたことと合う側、速く 1 つに決まる側。

## 各点の選択肢

### 1. D3 の誤の記号
- **A（推奨）E9**: 誤の原因の表を変えない。説明の文で何が起きたか分かる。
- B 不明（22 節）: 正誤ははっきりしている（宛先は local で反しない）ので、不明にする理由が弱い。
- C 新しい記号 E10: 封の前なら足せるが、語彙を増やすと付録・道具の直しが要る。

### 2. 位置を読む順
- **A（推奨）`locations` の順**: 判定表に並んだ順で、誰がやっても同じ。最初に正と分かった位置は `note` に書く。
- B 判定者が読みやすい順: 速いが、ラベルの付き方が人によって変わる。

### 3. 一部の値のときだけ反する形の条件
- A 前の例の読み `なし`（行には毎回届く）: 速いが、14.3 の「環境が変わるのは一部」の行（D76）と考え方がずれる。
- **B（推奨）反する場合の条件を書く**: D76 の行と同じ考え方。(C)（条件なしの数）には入らない。

### 4. 応答しだいの効果
- **A（推奨）14.3 の規則どおり**: すでにある規則（2 つに読めるときは表の上のもの）を当てるだけ。
- B いつも `外部の状態`: 速いが、引数で起こせる形を区別できない。

### 5. 接頭辞
- A 「不明:」（前の例の読み）。
- **B（推奨）「その他:」**: 16.2 の接頭辞の決まりは「種類が分かっていて表に無い → その他、決められない → 不明」。受け渡しファイルは何かが分かっている。

### 6. 設定ファイル
- A いつも キャッシュ・状態の保存（前の例の読み）。
- **B（推奨）読み返す主語で分ける**: ツールが自分で保存して読み返すならキャッシュ・状態の保存、利用者が編集する設定（利用者が開いて直すファイル）なら 利用者のファイル。
- C いつも 利用者のファイル。

### 7. 呼び戻しの理由の類
- A その他（前の例の読み）。 B 外の値。
- **C（推奨）動的な呼び出し**: 「いつ・どこから呼ばれるか」が外のコードで決まる、という中身に一番近い。

### 8. 包む部品の起動フック
- **A（推奨）到達する（`起動の方法`）**: 14.4 の `main()` の行と同じ理屈。(B)(C) には入らない。
- B 不明: 起動の方法はコードから読めるので、不明にする理由が弱い。

### 9. 運用者が決めるコマンド
- **A（推奨）分かれば判定・分からなければ不明**: 判定するのは木にあるコードの動作。
- B 「書き込むプログラムを設定すれば違反」として正（`運用者の設定`）: 木に無いコードを違反と数えることになり、強すぎる。

### 10. 到達は決められないが反しない
- **A（推奨）誤（E8）**: 「両方が『はい』のときだけ正」なので正にはならない。不明にすると精度の分母から外れ、精度を高く見せる向き。
- B 不明（表の字義）。

### 11. kind の取り違え
- **A（推奨）正**: 判定するのは動作で、解析器の説明ではない（11.2）。精度に「kind の付け方の正しさ」を混ぜない。
- B 誤（E4）: 手順 C の字義。精度を低く見せる向き。

### 12. 位置で `target_by_arg` が違う
- **A（推奨）最初に正と分かった位置**: `write_target` と同じ規則で、2 の読む順と合わせて 1 つに決まる。
- B どれか 1 つでも `はい` なら `はい`: 重い側に寄るが、止めてよい規則（手順 G）と合わない（全部読む必要が出る）。

### 13. DB の行
- **A（推奨）上の 3 分け**: 「どの行を変えるか」を引数が選ぶかで決める。
- B 引数が行の中身に入れば `はい`: ほとんどの DB 書き込みが `はい` になり、層の意味が薄くなる。

### 14. 機械翻訳
- **A（推奨）当たらない（`note` に道具を書く）**: 事実を調べる補助でもなく、判定の材料を作らない。コードと宣言を渡さない条件をつける。
- B 当たる（`ai_used: あり`、ログを残す）: 開示としては安全だが、記録の手間が増える。

### 15. API の名前
- **A（推奨）名前から決めてよい（はっきりしているときだけ）**: 15.1 の字義どおり。件数を報告して、名前だけで決めた件を読み手が外せるようにする。
- B 19 節を優先し、公式の文書かソースが無ければ不明: 厳しいが、不明が増える。

### 16. wrapper
- **A（推奨）深さの数え方だけの決まり（中は読む）**: wrapper の中の動作はツールを呼ぶたびに実行されるので、読まないと見落とす。
- B wrapper の中は読まない: 速いが、デコレータの中のログの書き込みなどを見落とす。
